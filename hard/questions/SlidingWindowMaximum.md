# Sliding Window Maximum（滑动窗口最大值）

给定一个整数数组 `nums` 和一个整数 `k`。有一个大小为 `k` 的滑动窗口，最开始位于数组最左侧。窗口每次向右移动一个位置，直到到达数组最右侧。

请返回一个列表，其中包含**每个窗口中的最大值**。

## 示例

```
输入：
nums = [1, 2, 1, 0, 4, 2, 6]
k = 3

输出：
[2, 2, 4, 4, 6]
```

窗口移动过程：

```
窗口位置                      最大值
-----------------------------------
[1  2  1] 0  4  2  6           2
 1 [2  1  0] 4  2  6           2
 1  2 [1  0  4] 2  6           4
 1  2  1 [0  4  2] 6           4
 1  2  1  0 [4  2  6]          6
```

设：

- `n = len(nums)`
- 一共有 `n - k + 1` 个滑动窗口。

------

# 1. 暴力法 Brute Force

## 思路

最直接的方法就是：

对于每一个长度为 `k` 的窗口，都重新遍历其中的 `k` 个元素，找出最大值。

例如窗口：

```
[1, 2, 1]
```

扫描三个元素，得到最大值 `2`。

然后窗口右移：

```
[2, 1, 0]
```

再次扫描三个元素。

这种方法非常直观，但存在大量重复计算。

例如：

```
[1, 2, 1]
   [2, 1, 0]
```

元素 `2, 1` 在连续两个窗口里都被重新扫描了。

## 算法

1. 创建 `output` 保存所有窗口的最大值。
2. 枚举每个窗口的起点 `i`。
3. 遍历 `[i, i + k - 1]` 中所有元素。
4. 找到最大值并加入 `output`。
5. 返回结果。

## Python

```
from typing import List


class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        output = []

        # 窗口起点 i：
        # 最后一个窗口的起点是 len(nums) - k
        for i in range(len(nums) - k + 1):
            maxi = nums[i]

            # 遍历当前窗口 [i, i + k - 1]
            for j in range(i, i + k):
                maxi = max(maxi, nums[j])

            output.append(maxi)

        return output
```

## 复杂度

- 时间复杂度：**O(nk)**
- 额外空间复杂度：**O(1)**
- 输出数组需要：**O(n - k + 1)**

如果 `k` 接近 `n`，最坏情况下复杂度接近：

```
O(n²)
```

因此通常无法通过数据规模较大的面试题。

# 2. 线段树 Segment Tree

## 核心思路

暴力法的问题是：

> 每次查询一个区间的最大值，都要重新遍历整个区间。

而线段树（Segment Tree）是一种专门用于解决**区间查询问题**的数据结构。

例如我们希望频繁回答：

```
nums[L:R] 中的最大值是多少？
```

可以先花时间构建一棵线段树，然后每次区间查询只需要：

```
O(log n)
```

因此对于滑动窗口：

```
[0, k-1]
[1, k]
[2, k+1]
...
```

我们只需要依次查询这些区间即可。

------

## 线段树是什么？

假设：

```
nums = [1, 2, 1, 0]
```

可以理解为构建类似：

```
             2
          /     \
         2       1
       /  \     / \
      1    2   1   0
```

每个节点保存：

> 它所代表区间中的最大值。

因此：

- 根节点保存整个数组最大值
- 左子树保存数组左半部分最大值
- 右子树保存数组右半部分最大值
- 叶子节点保存原数组元素

------

## 算法

### 第一步：构建 Segment Tree

先把数组元素放在树的叶子节点：

```
tree[n]
tree[n+1]
tree[n+2]
...
```

然后从下向上计算：

```
tree[i] = max(tree[2 * i], tree[2 * i + 1])
```

### 第二步：执行区间最大值查询

对于每个窗口：

```
[i, i + k - 1]
```

在线段树中查询最大值。

一次查询：

```
O(log n)
```

### 第三步：遍历所有窗口

共有：

```
n - k + 1
```

个窗口。

------

## Python

```
class SegmentTree:
    def __init__(self, N, A):
        # 将 self.n 扩展到不小于 N 的最小 2 的幂
        # 这样树的结构更加规整
        self.n = N

        while (self.n & (self.n - 1)) != 0:
            self.n += 1

        self.build(N, A)

    def build(self, N, A):
        # 用负无穷初始化。
        # 因为我们做的是 max 查询，
        # 空余节点不能影响最大值结果。
        self.tree = [float('-inf')] * (2 * self.n)

        # 原数组放到叶子节点
        for i in range(N):
            self.tree[self.n + i] = A[i]

        # 从下往上构建父节点
        for i in range(self.n - 1, 0, -1):
            left_child = i << 1
            right_child = i << 1 | 1

            self.tree[i] = max(
                self.tree[left_child],
                self.tree[right_child]
            )

    def query(self, l, r):
        """
        查询闭区间 [l, r] 的最大值
        """

        res = float('-inf')

        # 转换为叶子节点位置
        l += self.n

        # 将闭区间 [l, r] 转换成半开区间 [l, r + 1)
        r += self.n + 1

        while l < r:

            # 如果 l 是右孩子，
            # 当前节点无法再和左边兄弟一起组成完整区间，
            # 所以直接加入答案。
            if l & 1:
                res = max(res, self.tree[l])
                l += 1

            # 如果 r 是右边界，
            # 先向左移动，然后加入答案。
            if r & 1:
                r -= 1
                res = max(res, self.tree[r])

            # 向上一层
            l >>= 1
            r >>= 1

        return res


class Solution:
    def maxSlidingWindow(self, nums, k):
        n = len(nums)

        seg_tree = SegmentTree(n, nums)

        output = []

        # 查询每一个窗口
        for i in range(n - k + 1):
            window_max = seg_tree.query(i, i + k - 1)
            output.append(window_max)

        return output
```

## Python 位运算说明

这段代码中出现了几个比较具体的 Python / 位运算写法。

### `i << 1`

```
i << 1
```

表示：

```
i * 2
```

因为二进制左移一位，相当于乘以 `2`。

在线段树中：

```
i << 1
```

表示左孩子：

```
2 * i
```

------

### `i << 1 | 1`

表示：

```
2 * i + 1
```

也就是右孩子。

------

### `i >>= 1`

等价于：

```
i //= 2
```

表示移动到父节点。

------

### `i & 1`

判断一个整数是否为奇数：

```
if i & 1:
```

等价于：

```
if i % 2 == 1:
```

------

### `(n & (n - 1)) == 0`

这是一个经典技巧，用于判断：

> `n` 是否为 2 的幂。

例如：

```
8  = 1000
7  = 0111

8 & 7 = 0
```

所以：

```
(n & (n - 1)) == 0
```

说明 `n` 是 `2^x`。

------

## 复杂度

建立线段树：

```
O(n)
```

每个窗口查询：

```
O(log n)
```

窗口数量：

```
O(n)
```

因此总时间复杂度：

**O(n log n)**

空间复杂度：

**O(n)**

### 面试评价

这是一个合理解法，但并不是这道题最自然的解法。

Segment Tree 更适合这样的题：

> 数组中间的值会不断被修改，同时还需要不断进行区间最大值查询。

而本题数组本身不会变化，因此使用线段树有些“大材小用”。

# 3. 最大堆 Heap

## 核心思路

如果我们能够随时知道当前窗口中的最大值，问题就解决了。

Heap（堆）是一种非常适合维护最大值 / 最小值的数据结构。

最大堆支持：

```
快速查看最大值
```

但是 Python 标准库 `heapq` 只提供：

> **最小堆（Min Heap）**

因此需要通过一个技巧模拟最大堆。

如果数字：

```
10
```

存成：

```
-10
```

那么：

```
10 > 5
```

对应：

```
-10 < -5
```

于是最小的负数实际上对应原数组中最大的数字。

------

## 为什么 Heap 需要保存 index？

假设当前 Heap 最大值来自：

```
nums[2]
```

但窗口已经移动到了：

```
[3, 4, 5]
```

那么 `nums[2]` 已经不属于窗口。

所以 Heap 中不能只保存：

```
value
```

必须保存：

```
(value, index)
```

这样才能判断元素是否已经过期。

------

## 算法

遍历每个元素 `nums[i]`：

1. 将 `(-nums[i], i)` 加入最小堆。
2. 当第一个完整窗口形成后：
   - 检查堆顶元素是否已经离开窗口。
   - 如果离开，不断弹出。
3. 堆顶元素就是当前窗口最大值。
4. 将其加入答案。

------

## Python

```
import heapq
from typing import List


class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        heap = []
        output = []

        for i in range(len(nums)):

            # Python heapq 是最小堆。
            # 保存负数，从而模拟最大堆。
            #
            # tuple:
            # (-value, index)
            heapq.heappush(heap, (-nums[i], i))

            # 当已经形成一个完整窗口时
            if i >= k - 1:

                # 当前窗口：
                # [i - k + 1, i]
                #
                # 所以 index <= i - k 的元素已经离开窗口。
                while heap[0][1] <= i - k:
                    heapq.heappop(heap)

                # heap[0][0] 是负数，所以再取负号恢复原值
                output.append(-heap[0][0])

        return output
```

------

## `heapq` 说明

Python 标准库：

```
import heapq
```

提供最小堆。

### 插入

```
heapq.heappush(heap, value)
```

时间复杂度：

```
O(log n)
```

### 删除最小值

```
heapq.heappop(heap)
```

时间复杂度：

```
O(log n)
```

### 查看最小值

```
heap[0]
```

时间复杂度：

```
O(1)
```

------

## 为什么这里只删除堆顶的过期元素？

这是 Heap 解法里一个非常重要的思想：

> **Lazy Deletion（惰性删除）**

Heap 中可能存在已经离开窗口的旧元素，但是：

如果它不是最大值，我们根本不需要管它。

只有当某个过期元素跑到：

```
heap[0]
```

也就是准备影响答案的时候，我们才删除它。

因此：

```
while heap[0][1] <= i - k:
    heapq.heappop(heap)
```

一直删除到堆顶属于当前窗口为止。

------

## 复杂度

每个元素最多：

- 入堆一次
- 出堆一次

每次 Heap 操作：

```
O(log n)
```

因此：

- 时间复杂度：**O(n log n)**
- 空间复杂度：**O(n)**

注意这里由于使用了 Lazy Deletion，过期但没有到堆顶的元素可能仍然留在 Heap 中，因此最坏空间复杂度是 `O(n)`，而不是 `O(k)`。

# 4. 分块动态规划 / Prefix-Suffix Max

这类解法通常被称为：

- Block DP
- Prefix/Suffix Maximum
- Left/Right Max

虽然题解可能把它归类为 Dynamic Programming，但它和传统的状态转移 DP 并不完全一样。

## 核心思路

我们希望把：

```
每个窗口重新求最大值
```

变成：

```
预处理一次
+
每个窗口 O(1) 得到答案
```

关键是：

> 将数组按照大小 `k` 分成若干 Block（块）。

例如：

```
k = 3

nums =
[1, 2, 1] [0, 4, 2] [6, ...]
```

我们计算两个数组：

```
leftMax
rightMax
```

------

## `leftMax`

`leftMax[i]` 表示：

> 从当前 Block 左边界，到 `i` 的最大值。

例如：

```
nums:
[1, 2, 1] [0, 4, 2]

leftMax:
[1, 2, 2] [0, 4, 4]
```

注意每到一个新的 Block：

```
i % k == 0
```

就必须重新开始。

------

## `rightMax`

`rightMax[i]` 表示：

> 从 `i` 到当前 Block 右边界的最大值。

例如：

```
nums:
[1, 2, 1] [0, 4, 2]

rightMax:
[2, 2, 1] [4, 4, 2]
```

------

## 为什么这样能计算窗口最大值？

考虑窗口：

```
      i               i+k-1
      ↓                 ↓
... [ x x | x x x | x x ] ...
```

一个长度恰好为 `k` 的窗口：

> 最多横跨两个大小为 `k` 的 Block。

因此窗口可以被分成：

```
窗口左半部分
+
窗口右半部分
```

左半部分最大值：

```
rightMax[i]
```

右半部分最大值：

```
leftMax[i + k - 1]
```

所以：

```
window_max = max(
    rightMax[i],
    leftMax[i + k - 1]
)
```

------

## Python

```
from typing import List


class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)

        leftMax = [0] * n
        rightMax = [0] * n

        # 初始化两端
        leftMax[0] = nums[0]
        rightMax[n - 1] = nums[n - 1]

        for i in range(1, n):

            # --------------------------------
            # 构建 leftMax
            # --------------------------------

            # 每 k 个元素开始一个新的 block
            if i % k == 0:
                leftMax[i] = nums[i]
            else:
                leftMax[i] = max(
                    leftMax[i - 1],
                    nums[i]
                )

            # --------------------------------
            # 构建 rightMax
            # --------------------------------

            j = n - 1 - i

            # 如果 j 是某个 block 的左边界，
            # 从 nums[j] 重新开始。
            if j % k == 0:
                rightMax[j] = nums[j]
            else:
                rightMax[j] = max(
                    rightMax[j + 1],
                    nums[j]
                )

        # 一共有 n - k + 1 个窗口
        output = [0] * (n - k + 1)

        for i in range(n - k + 1):
            output[i] = max(
                rightMax[i],
                leftMax[i + k - 1]
            )

        return output
```

这里稍微重写了原答案中的 `rightMax` 部分，使 Block 边界更加直观。

------

## 复杂度

构造：

```
leftMax  → O(n)
rightMax → O(n)
```

遍历所有窗口：

```
O(n)
```

因此：

- 时间复杂度：**O(n)**
- 空间复杂度：**O(n)**

### 优点

已经达到了最优时间复杂度：

```
O(n)
```

### 缺点

需要额外两个长度为 `n` 的数组，因此空间：

```
O(n)
```

而下面的 Monotonic Deque 可以做到：

```
O(n) 时间
O(k) 空间
```

# 5. 单调队列 Monotonic Deque —— 推荐掌握

这是这道题最经典、也是代码面试中最值得掌握的解法。

## 核心思路

使用一个：

> **Monotonically Decreasing Deque（单调递减双端队列）**

Deque 中不直接存数字，而是存：

```
数组下标 index
```

并且始终保证：

```
nums[q[0]] >= nums[q[1]] >= nums[q[2]] >= ...
```

因此：

```
q[0]
```

对应的元素永远是当前窗口的最大值。

------

# 为什么可以删除比新元素小的旧元素？

这是整个算法最核心的地方。

假设当前 Deque 中存在：

```
旧元素：3
```

现在来了一个：

```
新元素：5
```

并且 `5` 在 `3` 的右边：

```
... 3 ... 5
```

考虑未来的窗口。

只要 `3` 还在窗口里：

```
5
```

一定也还在窗口里，因为 `5` 比 `3` 更晚进入窗口。

而且：

```
5 > 3
```

所以 `3`：

- 比 `5` 小
- 又比 `5` 更早离开窗口

它永远不可能再成为最大值。

因此可以永久删除。

这是一种：

> **Dominance / 淘汰思想**

新来的、更大的元素彻底支配旧的、更小的元素。

------

## 示例

```
nums = [1, 2, 1, 0, 4, 2, 6]
k = 3
```

开始：

```
1
Deque: [1]
```

加入 `2`：

```
1 < 2
```

删除 `1`：

```
Deque: [2]
```

加入 `1`：

```
Deque: [2, 1]
```

此时窗口：

```
[1, 2, 1]
```

Deque 头部：

```
2
```

所以最大值是 `2`。

继续加入：

```
0
```

Deque：

```
[2, 1, 0]
```

但是最左边的 `2` 对应下标即将离开窗口。

继续移动时把它删除即可。

------

# 为什么 Deque 存 index 而不是 value？

考虑：

```
nums = [5, 1, 5]
```

如果 Deque 只保存：

```
5
```

我们无法知道：

> 这个 `5` 是 `nums[0]` 还是 `nums[2]`？

也就无法判断：

> 它什么时候离开窗口。

所以应该存：

```
index
```

需要数字时再访问：

```
nums[index]
```

------

## 算法

对于每一个右边界 `r`：

### 1. 维护单调递减性

```
while q and nums[q[-1]] < nums[r]:
    q.pop()
```

如果新元素更大，就从队尾不断删除更小元素。

然后：

```
q.append(r)
```

------

### 2. 删除已经离开窗口的下标

如果：

```
q[0] < 当前窗口左边界
```

说明队首元素已经离开窗口：

```
q.popleft()
```

------

### 3. 窗口形成后记录答案

当：

```
r >= k - 1
```

第一个完整窗口形成。

因为 Deque 保持递减：

```
nums[q[0]]
```

一定是当前最大值。

------

## 推荐写法

相比原答案，我更推荐下面这个版本。窗口边界更加明确，也是面试中比较容易解释的写法。

```
from collections import deque
from typing import List


class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        output = []

        # q 保存元素的下标。
        #
        # 并且保证：
        # nums[q[0]] >= nums[q[1]] >= nums[q[2]] ...
        q = deque()

        for right in range(len(nums)):

            # ---------------------------------
            # 1. 删除队尾所有比当前元素小的元素
            # ---------------------------------
            #
            # 这些元素：
            # - 比 nums[right] 小
            # - 又比 nums[right] 更早离开窗口
            #
            # 所以以后永远不可能成为窗口最大值。
            while q and nums[q[-1]] < nums[right]:
                q.pop()

            q.append(right)

            # 当前窗口左边界
            left = right - k + 1

            # ---------------------------------
            # 2. 删除已经离开窗口的元素
            # ---------------------------------
            if q[0] < left:
                q.popleft()

            # ---------------------------------
            #3. 完整窗口已经形成
            # ---------------------------------
            if right >= k - 1:
                # q[0] 对应当前窗口最大值
                output.append(nums[q[0]])

        return output
```

------

# `collections.deque` 说明

Python 中双端队列来自：

```
from collections import deque
```

创建：

```
q = deque()
```

Deque 与普通 `list` 最大的区别之一是：

> 可以在两端高效插入和删除。

常见操作：

```
q.append(x)
```

右侧加入：

```
O(1)
q.pop()
```

右侧删除：

```
O(1)
q.appendleft(x)
```

左侧加入：

```
O(1)
q.popleft()
```

左侧删除：

```
O(1)
```

为什么这里不用：

```
list.pop(0)
```

因为 Python List 删除第一个元素需要把后面的元素整体向前移动：

```
O(n)
```

而：

```
deque.popleft()
```

是：

```
O(1)
```

所以滑动窗口 / BFS 等算法经常使用 `deque`。

------

# 为什么 Deque 解法是 O(n)？

乍一看代码里有：

```
for ...
    while ...
```

可能会误以为复杂度是：

```
O(n²)
```

但实际上不是。

考虑每一个数组元素。

一个元素最多：

1. 被 `append()` 加入 Deque 一次；
2. 被 `pop()` 或 `popleft()` 删除一次。

也就是说：

```
每个元素最多进入一次
每个元素最多离开一次
```

对于 `n` 个元素：

```
总 push ≤ n
总 pop ≤ n
```

因此总操作数量仍然是：

```
O(n)
```

这种分析方法称为：

> **Amortized Analysis（摊还分析）**

------

## 复杂度

- 时间复杂度：**O(n)**
- 空间复杂度：**O(k)**

为什么空间是 `O(k)`？

Deque 中只需要维护和当前窗口相关的候选元素，因此最多保存约 `k` 个下标。

这比 Block DP 的：

```
O(n)
```

更节省空间。

------

# 五种解法对比

| 方法                | 时间复杂度 | 额外空间 | 面试推荐度 |
| ------------------- | ---------- | -------- | ---------- |
| 暴力法              | O(nk)      | O(1)     | ★          |
| Segment Tree        | O(n log n) | O(n)     | ★★         |
| Heap                | O(n log n) | O(n)     | ★★★        |
| Block DP            | O(n)       | O(n)     | ★★★★       |
| **Monotonic Deque** | **O(n)**   | **O(k)** | **★★★★★**  |

对于这道题，最值得掌握的是：

```
Monotonic Deque
```

因为它同时达到了：

```
O(n) 时间
+
O(k) 空间
```

而且这种思想可以迁移到很多其他题目。

------

# 面试中如何推导到 Monotonic Deque

一个比较自然的思考顺序是：

### 第一步：暴力法

每个窗口都求一次：

```
max(window)
```

复杂度：

```
O(nk)
```

然后思考：

> 相邻窗口之间有大量重复元素，能不能复用之前的信息？

------

### 第二步：我们真正需要保存什么？

窗口里并不是所有元素都有价值。

例如：

```
[8, 3, 5]
```

当 `5` 出现以后：

```
3
```

其实已经没有意义。

因为：

```
5 > 3
```

并且 `5` 比 `3` 更晚离开窗口。

所以：

```
3 永远不可能成为未来窗口最大值
```

可以删除。

------

### 第三步：只保留“潜在最大值”

例如：

```
nums = [9, 7, 5, 6]
```

处理前三个：

```
9, 7, 5
```

都是潜在最大值，因为：

```
9 离开后可能是 7
7 离开后可能是 5
```

但 `6` 出现：

```
9, 7, 5, 6
```

此时：

```
5 < 6
```

而且 `5` 更早离开，因此 `5` 永远不会成为最大值。

删除：

```
9, 7, 6
```

于是自然得到：

> 维护一个递减的数据结构。

又因为我们既要：

```
从右侧加入新元素
```

又要：

```
从左侧删除过期元素
```

因此：

```
Deque
```

正好适合。

# 常见错误 Common Pitfalls

## 1. Deque 中保存 value 而不是 index

错误思路：

```
q.append(nums[right])
```

这样无法知道某个数字什么时候离开窗口。

正确做法：

```
q.append(right)
```

访问数字：

```
nums[q[0]]
```

核心原则：

```
Deque 保存 index
nums[index] 才是 value
```

------

## 2. 窗口边界 Off-by-One

长度为 `k` 的第一个完整窗口，其右边界是：

```
k - 1
```

因此：

```
if right >= k - 1:
```

才开始记录答案。

例如：

```
k = 3
```

第一个窗口：

```
index: 0 1 2
```

所以：

```
right = 2 = k - 1
```

------

## 3. 忘记删除窗口外元素

当前窗口：

```
[left, right]
```

如果：

```
q[0] < left
```

说明 Deque 队首已经离开窗口：

```
q.popleft()
```

也可以直接通过：

```
if q[0] <= right - k:
```

判断。

因为：

```
left = right - k + 1
```

所以：

```
index < left
```

等价于：

```
index <= right - k
```

------

## 4. 没有维护 Deque 单调性

加入 `nums[right]` 之前：

```
while q and nums[q[-1]] < nums[right]:
    q.pop()
```

必须删除队尾更小的元素。

否则：

```
q[0]
```

虽然一开始可能是最大值，但整个 Deque 不再具有“候选最大值队列”的性质。

------

## 5. `<` 和 `<=` 到底应该用哪个？

原题解析把使用 `<=` 描述成错误，这并不准确。

下面两种写法都可以正确解决问题：

```
while q and nums[q[-1]] < nums[right]:
    q.pop()
```

以及：

```
while q and nums[q[-1]] <= nums[right]:
    q.pop()
```

区别在于如何处理重复值。

假设：

```
nums = [5, 5]
```

使用 `<`：

```
保留两个 5
```

Deque 可能是：

```
[index 0, index 1]
```

使用 `<=`：

```
删除旧的 5，只留下新的 5
```

Deque 变成：

```
[index 1]
```

两种都正确。

使用 `<=` 的逻辑是：

> 如果两个值相同，新的元素更晚离开窗口，因此旧元素其实也可以被淘汰。

使用 `<` 则：

> 保留重复值，并通过窗口边界自然删除旧元素。

面试中任选一种即可，只要逻辑保持一致。

------

## 6. Output 长度写错

长度为 `n` 的数组中，长度为 `k` 的窗口数量为：

```
n - k + 1
```

例如：

```
n = 7
k = 3
```

窗口起点：

```
0
1
2
3
4
```

一共：

```
5 = 7 - 3 + 1
```

特别注意：

```
k == n
```

时依然应该有：

```
1
```

个窗口。

------

## 7. Segment Tree 的闭区间 / 半开区间混淆

窗口从 `i` 开始、长度为 `k`：

```
[i, i + k - 1]
```

这是一个**两端都包含的闭区间**。

Python 切片则通常是半开区间：

```
nums[i:i + k]
```

表示：

```
[i, i + k)
```

这两种表达对应的是同一个长度为 `k` 的窗口。

Segment Tree 查询时必须特别注意 API 使用的是：

```
[L, R]
```

还是：

```
[L, R)
```

这是线段树题目中非常常见的 bug 来源。

# 最后需要重点掌握的模式

这道题真正值得带走的并不是五种具体代码，而是以下几个算法模式。

### 1. Sliding Window

当题目出现：

```
固定长度连续子数组
连续区间
窗口不断右移
```

应该首先想到：

```
Sliding Window
```

------

### 2. Heap + Lazy Deletion

当我们需要动态维护：

```
最大值 / 最小值
```

但旧数据不会方便地从 Heap 中任意删除时，可以考虑：

```
(value, index)
+
Lazy Deletion
```

即：

> 暂时不删除无效元素，等它真正影响堆顶答案时再删除。

------

### 3. Monotonic Data Structure

当问题涉及：

```
连续区间最大值
连续区间最小值
Next Greater Element
Next Smaller Element
```

应该对：

```
Monotonic Stack
Monotonic Queue / Deque
```

保持敏感。

这道题最核心的思想可以概括成一句话：

> **一个更大、并且出现得更晚的元素，会永久淘汰一个更小、出现得更早的元素。**

因此我们只保留仍然有机会成为未来最大值的元素。

这正是 Monotonic Deque 能够把复杂度降低到 **O(n)** 的原因。
