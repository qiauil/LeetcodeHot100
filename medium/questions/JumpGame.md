# Jump Game（跳跃游戏）

给定一个整数数组 `nums`，其中 `nums[i]` 表示你在索引 `i` 处**最多可以向前跳多少步**。

如果从索引 `0` 出发能够到达最后一个索引，返回 `True`；否则返回 `False`。

例如：

```
nums = [2, 3, 1, 1, 4]
```

从索引 `0` 出发，最多可以跳 `2` 步，因此可以选择跳到索引 `1`。
在索引 `1`，最多可以跳 `3` 步，因此可以直接跳到最后一个索引 `4`。

所以答案为：

```
True
```

------

## 一、递归 / DFS

### 核心思路

我们可以把问题定义成：

> `dfs(i)`：从索引 `i` 出发，是否能够最终到达最后一个索引？

在位置 `i`：

```
nums[i]
```

表示**最大跳跃距离**，因此下一步并不是只能跳到：

```
i + nums[i]
```

而是可以选择：

```
i + 1
i + 2
...
i + nums[i]
```

中的任意位置。

因此最直接的方法就是：

> 尝试当前索引能够到达的所有位置，只要其中存在一条路径最终到达终点，就返回 `True`。

这实际上是在搜索一棵**决策树（Decision Tree）**。

例如：

```
nums = [2, 3, 1, 1, 4]

              0
            /   \
           1     2
        /  |  \   \
       2   3   4   3
               ↑
             到达终点
```

只要找到一条成功路径，就可以立即停止搜索。

### 算法步骤

1. 定义递归函数 `dfs(i)`，表示从索引 `i` 是否能够到达终点。
2. 如果 `i` 已经是最后一个索引，返回 `True`。
3. 计算当前位置最远能够到达哪里：

```
end = min(len(nums), i + nums[i] + 1)
```

1. 枚举所有可能的下一跳：

```
i + 1, i + 2, ..., i + nums[i]
```

1. 如果其中任何一个 `dfs(j)` 返回 `True`，立即返回 `True`。
2. 如果所有选择都失败，返回 `False`。

### Python 实现

```
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        n = len(nums)

        def dfs(i: int) -> bool:
            # Base Case：
            # 已经到达最后一个索引
            if i == n - 1:
                return True

            # Python range 的右边界不包含在范围内，
            # 所以这里需要 +1
            end = min(n, i + nums[i] + 1)

            # 尝试当前位置能够到达的所有下一位置
            for j in range(i + 1, end):
                if dfs(j):
                    return True

            # 所有路径都无法到达终点
            return False

        return dfs(0)
```

### 复杂度分析

递归方法存在大量重复计算，因此时间复杂度是**指数级**的。

更准确地说，通常可以粗略表示为：

- 时间复杂度：`O(2^n)` 量级
- 空间复杂度：`O(n)`

空间主要来自最深可能达到 `O(n)` 的递归调用栈。

> 原答案中将时间复杂度写成 `O(n!)` 并不太准确。这个问题的朴素递归搜索更常见的分析是指数级复杂度。

# 二、Top-Down 动态规划（Memoization）

## 核心思路

上面的递归有一个明显问题：**重复计算**。

例如：

```
        0
       / \
      1   2
       \ /
        3
```

不同路径可能都会到达索引 `3`，于是：

```
dfs(3)
```

可能被重复计算很多次。

但实际上：

> “从索引 `3` 能不能到达终点？”

这个问题的答案一旦计算出来，以后就没有必要重新计算。

因此我们使用一个 `memo` 保存结果：

```
memo[i] = 从索引 i 是否能够到达终点
```

这就是：

> **递归 + 缓存 = Top-Down Dynamic Programming**

------

## 算法步骤

1. 创建字典 `memo`。
2. 定义 `dfs(i)`。
3. 如果 `i` 已经存在于 `memo`，直接返回之前计算的结果。
4. 如果 `i` 是最后一个索引，返回 `True`。
5. 枚举当前位置所有可能的下一跳。
6. 如果存在某个位置能够到达终点：

```
memo[i] = True
```

1. 如果所有选择都失败：

```
memo[i] = False
```

1. 最终返回：

```
dfs(0)
```

------

## Python 实现

```
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        # memo[i] 表示：
        # 从索引 i 出发是否能够到达最后一个索引
        memo = {}

        def dfs(i: int) -> bool:
            # 如果之前计算过，直接使用缓存结果
            if i in memo:
                return memo[i]

            # 已经到达终点
            if i == len(nums) - 1:
                return True

            # nums[i] == 0 表示无法继续向前跳
            if nums[i] == 0:
                memo[i] = False
                return False

            # 最远能够到达的位置
            # range() 不包含右端点，因此需要 +1
            end = min(len(nums), i + nums[i] + 1)

            # 尝试所有可能的下一跳
            for j in range(i + 1, end):
                if dfs(j):
                    memo[i] = True
                    return True

            # 所有选择都失败
            memo[i] = False
            return False

        return dfs(0)
```

## `memo` 是什么？

这里：

```
memo = {}
```

创建的是 Python 的 `dict`（字典 / 哈希表）。

例如：

```
memo[3] = True
memo[5] = False
```

表示：

```
从索引 3 可以到达终点
从索引 5 无法到达终点
```

查询：

```
if i in memo:
```

平均时间复杂度为 `O(1)`。

------

## 复杂度分析

一共有 `n` 个状态：

```
dfs(0)
dfs(1)
...
dfs(n - 1)
```

由于 Memoization，每个状态最多真正计算一次。

但是对于每个 `i`，最坏情况下仍然可能检查 `O(n)` 个下一位置。

因此：

- 时间复杂度：`O(n²)`
- 空间复杂度：`O(n)`

空间包括：

- `memo`：`O(n)`
- 递归调用栈：最坏 `O(n)`

------

# 三、Bottom-Up 动态规划

## 核心思路

Top-Down DP 的状态定义是：

```
dfs(i) = 从 i 出发是否能够到达终点
```

我们可以直接把它转换成数组：

```
dp[i]
```

其中：

> `dp[i] == True` 表示从索引 `i` 出发能够到达最后一个索引。

最后一个位置显然可以“到达自己”，所以：

```
dp[n - 1] = True
```

然后从右往左计算。

对于当前位置 `i`：

> 只要 `i` 能跳到某个 `dp[j] == True` 的位置，那么 `dp[i]` 也应该是 `True`。

因此状态转移可以写成：

```
dp[i] = 是否存在某个 j：

i < j <= i + nums[i]

并且：

dp[j] == True
```

------

## 算法步骤

1. 创建长度为 `n` 的布尔数组：

```
dp = [False] * n
```

1. 初始化：

```
dp[n - 1] = True
```

1. 从右向左遍历：

```
n - 2 → ... → 1 → 0
```

1. 对于每个 `i`，检查它能够跳到的位置。
2. 如果其中存在：

```
dp[j] == True
```

则：

```
dp[i] = True
```

1. 最终返回：

```
dp[0]
```

------

## Python 实现

```
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        n = len(nums)

        # dp[i]：
        # 从索引 i 出发是否能够到达最后一个索引
        dp = [False] * n

        # 最后一个位置一定可以到达自己
        dp[-1] = True

        # 从倒数第二个位置开始向左计算
        for i in range(n - 2, -1, -1):

            # 当前索引最远能够跳到的位置
            end = min(n, i + nums[i] + 1)

            # 检查当前位置能否跳到某个“好位置”
            for j in range(i + 1, end):
                if dp[j]:
                    dp[i] = True
                    break

        return dp[0]
```

------

## `range(n - 2, -1, -1)` 的含义

这是 Python 面试中非常常见的写法：

```
range(start, stop, step)
```

这里：

```
range(n - 2, -1, -1)
```

表示：

```
n-2, n-3, n-4, ..., 2, 1, 0
```

注意 `range()` **不包含 `stop`**。

所以：

```
range(4, -1, -1)
```

产生：

```
4, 3, 2, 1, 0
```

这是一种非常常见的**倒序遍历数组**的方法。

------

## 复杂度分析

最坏情况下：

- 外层循环执行 `n` 次；
- 每个位置可能检查 `O(n)` 个下一位置。

因此：

- 时间复杂度：`O(n²)`
- 空间复杂度：`O(n)`

------

# 四、贪心算法 Greedy —— 最优解

这是这道题面试中最值得掌握的方法。

## 核心思路

Bottom-Up DP 中，我们实际上是在寻找：

> 哪些位置是能够到达终点的“好位置（good position）”？

但仔细观察后会发现：

**我们其实不需要保存所有好位置。**

只需要保存：

> 当前最靠左的、确定能够到达终点的位置。

用：

```
goal
```

表示这个位置。

最开始：

```
goal = len(nums) - 1
```

因为终点自己当然可以到达终点。

然后从右往左遍历。

对于索引 `i`，如果：

```
i + nums[i] >= goal
```

说明：

```
i ---------> goal ---------> 最终终点
```

既然从 `i` 能到达一个已经确定可以到终点的位置，那么：

> `i` 本身也一定可以到达终点。

于是更新：

```
goal = i
```

不断向左移动 `goal`。

------

## 示例

考虑：

```
nums = [2, 3, 1, 1, 4]
index   0  1  2  3  4
```

初始：

```
goal = 4
```

### 检查 `i = 3`

```
3 + nums[3]
= 3 + 1
= 4
```

能够到达 `goal = 4`。

所以：

```
goal = 3
```

### 检查 `i = 2`

```
2 + nums[2]
= 2 + 1
= 3
```

能够到达当前 `goal = 3`。

所以：

```
goal = 2
```

### 检查 `i = 1`

```
1 + 3 = 4 >= 2
```

所以：

```
goal = 1
```

### 检查 `i = 0`

```
0 + 2 = 2 >= 1
```

所以：

```
goal = 0
```

最终：

```
goal == 0
```

因此答案为：

```
True
```

------

## Python 实现

```
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        # goal 表示：
        # 当前最靠左的、确定能够到达最终终点的位置
        goal = len(nums) - 1

        # 从倒数第二个位置开始向左遍历
        for i in range(len(nums) - 2, -1, -1):

            # 如果从当前位置可以到达 goal
            # 那么当前位置本身也成为一个“好位置”
            if i + nums[i] >= goal:
                goal = i

        # 如果 goal 最终移动到了 0，
        # 说明从起点可以到达终点
        return goal == 0
```

# 五、为什么贪心算法是正确的？

这是面试中可能比代码本身更重要的部分。

假设我们已经知道：

```
goal
```

一定能够到达最终终点。

现在考虑左边的某个位置 `i`。

如果：

```
i + nums[i] >= goal
```

那么从 `i` 至少可以跳到 `goal`。

而我们已经知道：

```
goal → 最终终点
```

所以自然有：

```
i → goal → 最终终点
```

因此 `i` 也是一个能够到达终点的位置。

我们就可以安全地执行：

```
goal = i
```

也就是说：

> 每次找到一个更靠左、能够到达当前 `goal` 的位置，就把它作为新的 `goal`。

最终，如果：

```
goal == 0
```

就证明存在：

```
0 → ... → 最后一个索引
```

的路径。

------

# 六、从 DP 到 Greedy 的思维演进

这道题非常适合用来理解：

> **递归 → Memoization → DP → Greedy**

这几种算法之间的关系。

### 1. Recursion

思考：

```
从当前位置出发，尝试所有可能的下一步。
```

问题：

```
存在大量重复计算
```

复杂度：

```
指数级
```

### 2. Top-Down DP

发现：

```
dfs(i)
```

被重复计算。

于是：

```
把 dfs(i) 的结果缓存下来
```

复杂度降低为：

```
O(n²)
```

### 3. Bottom-Up DP

进一步发现递归其实不是必须的：

```
dp[i] = 从 i 能否到达终点
```

可以直接从右向左计算。

复杂度：

```
时间 O(n²)
空间 O(n)
```

### 4. Greedy

继续观察 DP：

```
dp[i] = True
```

只需要知道：

> `i` 是否能够到达某个已经确定可以到终点的位置。

因此根本不需要保存整个：

```
dp = [...]
```

只需要维护最左侧的好位置：

```
goal
```

最终得到：

```
时间 O(n)
空间 O(1)
```

这个思维过程非常值得掌握：

```
暴力搜索
   ↓
发现重复子问题
   ↓
Memoization
   ↓
Bottom-Up DP
   ↓
观察 DP 状态是否存在冗余
   ↓
Greedy
```

# 七、常见错误

## 1. 把 `nums[i]` 当成目标索引

错误理解：

```
next_index = nums[i]
```

或者认为必须跳：

```
i + nums[i]
```

实际上 `nums[i]` 表示的是：

> **最大跳跃距离**

所以从 `i` 可以选择：

```
i + 1
i + 2
...
i + nums[i]
```

任意一个位置。

------

## 2. 错误处理 `0`

如果：

```
nums[i] == 0
```

意味着：

> 从 `i` 无法继续向前移动。

但这**不意味着数组中出现 `0` 就一定失败**。

例如：

```
[2, 0, 1]
```

可以：

```
0 → 2
```

直接跳过索引 `1` 的 `0`。

真正的问题是：

> 是否被迫停在一个无法继续前进的 `0` 上。

------

## 3. Greedy 中写错判断条件

关键条件是：

```
i + nums[i] >= goal
```

而不是：

```
i + nums[i] == goal
```

因为只要能够**到达或者超过** `goal`，就说明当前位置可以连接到一条成功路径。

------

## 4. 忘记 Python `range()` 不包含右边界

例如：

```
range(i + 1, end)
```

不会访问 `end`。

因此如果当前位置最多能够跳：

```
nums[i]
```

步，一种方便的写法是：

```
end = min(len(nums), i + nums[i] + 1)

for j in range(i + 1, end):
    ...
```

其中 `+1` 正是为了处理 Python 的右开区间。

------

# 八、面试重点总结

这道题最终建议重点掌握 **Greedy**：

```
class Solution:
    def canJump(self, nums: List[int]) -> bool:
        goal = len(nums) - 1

        for i in range(len(nums) - 2, -1, -1):
            if i + nums[i] >= goal:
                goal = i

        return goal == 0
```

核心判断只有一句：

```
if i + nums[i] >= goal:
    goal = i
```

可以把它理解成：

> **如果当前位置能够到达一个已经确认可以到终点的位置，那么当前位置也可以到终点。**

四种方法的复杂度对比：

| 方法         | 时间复杂度 | 空间复杂度 | 面试推荐 |
| ------------ | ---------- | ---------- | -------- |
| Recursion    | 指数级     | `O(n)`     | ⭐        |
| Top-Down DP  | `O(n²)`    | `O(n)`     | ⭐⭐⭐      |
| Bottom-Up DP | `O(n²)`    | `O(n)`     | ⭐⭐⭐      |
| **Greedy**   | **`O(n)`** | **`O(1)`** | ⭐⭐⭐⭐⭐    |

如果面试官要求从基础方案逐步优化，一个非常自然的讲解顺序就是：

```
Recursion
    ↓
发现重复子问题
    ↓
Memoization / Top-Down DP
    ↓
Bottom-Up DP
    ↓
发现不需要保存整个 dp
    ↓
Greedy：只维护 goal
```

其中最值得记住的状态定义分别是：

```
# DFS / DP
dp[i] = 从位置 i 出发是否能够到达终点

# Greedy
goal = 当前最靠左的、确定能够到达终点的位置
```

这两个定义基本就是整道题的核心。
