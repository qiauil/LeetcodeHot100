# Unique Paths（不同路径）

## 题目

有一个 **`m x n`** 的网格。任意时刻，你只能向 **右** 或向 **下** 移动。

给定两个整数 **`m`** 和 **`n`**，返回从网格左上角 **`grid[0][0]`** 到右下角 **`grid[m - 1][n - 1]`** 一共有多少条不同的路径。

可以假设最终答案一定能够存储在 **32 位整数** 中。

------

# 一、核心思路

对于任意一个位置 `(i, j)`，因为只能向右或者向下走，所以：

```
当前位置的路径数
=
向右走之后的路径数
+
向下走之后的路径数
```

也就是：

\[ f(i,j)=f(i,j+1)+f(i+1,j) \]

这实际上就是这道题最核心的 **状态转移方程**。

从这个公式出发，可以自然得到：

1. 暴力递归
2. 记忆化搜索（Top-Down DP）
3. 二维动态规划（Bottom-Up DP）
4. 一维动态规划
5. 原地更新的一维动态规划
6. 组合数学

面试中最值得掌握的是 **记忆化搜索 → Bottom-Up DP → 一维空间优化 → 组合数学** 这一演进过程。

------

# 二、方法 1：递归（Brute Force）

## 思路

最直接的方法就是使用 DFS（Depth-First Search，深度优先搜索）。

假设当前位于 `(i, j)`：

- 向右走到 `(i, j + 1)`
- 向下走到 `(i + 1, j)`

因此：

```
dfs(i, j) = dfs(i, j + 1) + dfs(i + 1, j)
```

递归需要两个终止条件：

- 如果到达终点 `(m - 1, n - 1)`，说明找到了一条完整路径，返回 `1`。
- 如果走出了网格，说明这条路径无效，返回 `0`。

## 代码

```
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:

        def dfs(i, j):
            # 到达右下角，找到一条有效路径
            if i == m - 1 and j == n - 1:
                return 1

            # 超出网格范围，这条路径无效
            if i >= m or j >= n:
                return 0

            # 当前路径数 = 向右走的路径数 + 向下走的路径数
            return dfs(i, j + 1) + dfs(i + 1, j)

        return dfs(0, 0)
```

## 为什么效率很低？

因为存在大量 **重复子问题（overlapping subproblems）**。

例如，从 `(0, 0)` 出发：

```
             (0,0)
            /     \
         (0,1)   (1,0)
           \       /
             (1,1)
```

`(1,1)` 可以通过不同路径到达，而每次到达 `(1,1)` 时，我们都会重新计算：

```
dfs(1, 1)
```

网格越大，重复计算越严重。

## 复杂度

- **时间复杂度：`O(2^(m+n))`**
- **空间复杂度：`O(m+n)`**

空间主要来自递归调用栈。由于每次只会向右或向下移动，所以一条递归路径的最大深度约为 `m + n`。

> 更严格地说，有效路径的数量与组合数有关，因此 `O(2^(m+n))` 是一个常用的指数级上界。重点是：暴力递归的时间复杂度是指数级的。

------

# 三、方法 2：动态规划——记忆化搜索（Top-Down DP）

## 思路

暴力递归最大的问题是：

> 同一个 `(i, j)` 会被重复计算很多次。

但我们可以发现：

```
dfs(i, j)
```

的答案只由 `(i, j)` 决定。

所以第一次计算完之后，把结果保存起来；以后再次遇到 `(i, j)`，直接返回之前的结果。

这种技术叫：

**Memoization（记忆化）**

它通常也被称为 **Top-Down Dynamic Programming（自顶向下动态规划）**。

## 代码

```
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # -1 表示这个状态还没有计算过
        memo = [[-1] * n for _ in range(m)]

        def dfs(i, j):
            # 到达终点
            if i == m - 1 and j == n - 1:
                return 1

            # 越界
            if i >= m or j >= n:
                return 0

            # 已经计算过，直接返回缓存结果
            if memo[i][j] != -1:
                return memo[i][j]

            # 计算并缓存结果
            memo[i][j] = dfs(i, j + 1) + dfs(i + 1, j)

            return memo[i][j]

        return dfs(0, 0)
```

## Python：二维数组初始化

这里有一个很常见的 Python 写法：

```
memo = [[-1] * n for _ in range(m)]
```

含义是创建一个 `m x n` 的二维数组：

```
[
    [-1, -1, -1, ...],
    [-1, -1, -1, ...],
    ...
]
```

其中：

```
[-1] * n
```

创建长度为 `n` 的列表。

而：

```
for _ in range(m)
```

执行 `m` 次。

`_` 在 Python 中通常表示：

> 我需要循环这么多次，但是不关心当前循环变量的值。

### 一个 Python 常见陷阱

创建二维数组时，不推荐：

```
memo = [[-1] * n] * m
```

因为这样创建出来的每一行实际上引用的是 **同一个 list 对象**。

例如：

```
a = [[0] * 3] * 3
a[0][0] = 1

print(a)
```

可能得到：

```
[
    [1, 0, 0],
    [1, 0, 0],
    [1, 0, 0]
]
```

所以二维数组通常应该写成：

```
a = [[0] * n for _ in range(m)]
```

## 复杂度

网格中一共只有：

\[ m \times n \]

个不同状态。

每个状态只计算一次，因此：

- **时间复杂度：`O(m \* n)`**
- **空间复杂度：`O(m \* n)`**

此外还有递归调用栈 `O(m+n)`，但整体仍然由 `O(m*n)` 主导。

------

# 四、方法 3：动态规划——Bottom-Up

## 思路

前面的 Top-Down 是：

```
从起点开始
→ 不断问后面的状态
→ 最终到达终点
```

Bottom-Up 则反过来：

```
先知道终点附近的答案
→ 再一步一步计算前面的答案
→ 最终得到起点
```

定义：

```
dp[i][j]
=
从 (i,j) 到右下角的路径数量
```

因为 `(i, j)` 只能：

- 向下到 `(i + 1, j)`
- 向右到 `(i, j + 1)`

所以：

\[ dp[i][j] = dp[i+1][j] + dp[i][j+1] \]

## 为什么要从右下往左上计算？

因为计算：

```
dp[i][j]
```

之前必须已经知道：

```
dp[i + 1][j]   # 下方
dp[i][j + 1]   # 右方
```

所以遍历方向应该是：

```
从下往上
从右往左
```

## 代码

```
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # 多创建一行和一列，可以避免单独判断边界
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        # 终点本身有 1 种“路径”
        dp[m - 1][n - 1] = 1

        # 从右下角向左上角计算
        for i in range(m - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                dp[i][j] += dp[i + 1][j] + dp[i][j + 1]

        return dp[0][0]
```

## 为什么创建 `(m+1) x (n+1)`？

这是一个非常常见的 DP 技巧：

**Padding（增加额外边界）**

如果只创建：

```
m x n
```

的数组，那么：

```
dp[i + 1][j]
dp[i][j + 1]
```

可能越界。

创建：

```
(m + 1) x (n + 1)
```

之后，额外的一行和一列全部保持 `0`，就不需要写大量边界判断。

## `range(m - 1, -1, -1)`

这是 Python 中非常值得熟悉的倒序遍历：

```
range(start, stop, step)
```

所以：

```
range(m - 1, -1, -1)
```

表示：

```
m-1, m-2, ..., 2, 1, 0
```

注意 `stop=-1` **不会被包含**。

## 复杂度

- **时间复杂度：`O(m \* n)`**
- **空间复杂度：`O(m \* n)`**

------

# 五、方法 4：动态规划——空间优化

## 思路

观察二维 DP：

```
dp[i][j] = dp[i + 1][j] + dp[i][j + 1]
```

计算当前行的时候，我们实际上只需要：

- 当前行右侧的数据
- 下一行的数据

因此完全没有必要保存整个二维数组。

只保存 **一行** 即可。

假设：

```
row[j]
```

代表下面一行对应位置的答案。

创建：

```
newRow
```

计算当前行：

```
newRow[j] = newRow[j + 1] + row[j]
```

其中：

```
newRow[j + 1] → 右边
row[j]        → 下边
```

## 代码

```
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # 最后一行中，每个位置到终点都只有一种走法：
        # 一直向右
        row = [1] * n

        # 从倒数第二行开始，一行一行向上计算
        for _ in range(m - 1):
            newRow = [1] * n

            # 从右向左计算
            for j in range(n - 2, -1, -1):
                # 当前格 = 右边 + 下边
                newRow[j] = newRow[j + 1] + row[j]

            row = newRow

        return row[0]
```

## 复杂度

- **时间复杂度：`O(m \* n)`**
- **空间复杂度：`O(n)`**

相对于二维 DP：

```
O(m*n) → O(n)
```

空间已经明显优化。

------

# 六、方法 5：动态规划——原地更新的一维 DP

## 思路

方法 4 中其实还有一个地方可以优化。

我们使用了：

```
row
newRow
```

两个数组。

但实际上 `newRow` 也不需要。

可以直接在：

```
dp
```

上进行更新。

初始化：

```
dp = [1] * n
```

然后：

```
dp[j] += dp[j + 1]
```

这里最关键的是理解更新过程中两个值分别代表什么。

在执行：

```
dp[j] = dp[j] + dp[j + 1]
```

之前：

```
dp[j]     → 下方格子的路径数
dp[j + 1] → 当前行右方格子的路径数
```

因此正好对应：

\[ dp[i][j] = dp[i+1][j] + dp[i][j+1] \]

## 代码

```
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # 最后一行全部为 1
        dp = [1] * n

        # 从倒数第二行向上计算
        for _ in range(m - 2, -1, -1):

            # 必须从右向左更新
            for j in range(n - 2, -1, -1):
                # dp[j]：更新前代表下方
                # dp[j + 1]：已经更新，代表右方
                dp[j] += dp[j + 1]

        return dp[0]
```

实际上外层循环变量没有被使用，所以也可以写得更直观：

```
for _ in range(m - 1):
    for j in range(n - 2, -1, -1):
        dp[j] += dp[j + 1]
```

## 为什么必须从右向左？

因为：

```
dp[j]
```

需要：

```
旧 dp[j]       → 下方
新 dp[j + 1]   → 右方
```

所以必须保证 `j + 1` 已经更新，而 `j` 自己还没有更新。

这正是很多 **滚动数组 / 一维 DP** 问题中遍历方向非常重要的原因。

## 复杂度

- **时间复杂度：`O(m \* n)`**
- **空间复杂度：`O(n)`**

### 还能进一步优化空间

因为 `m` 和 `n` 的角色本质上是对称的，所以可以让一维数组始终使用较短的维度：

```
if n > m:
    m, n = n, m
```

这样空间复杂度可以写成：

\[ O(\min(m,n)) \]

------

# 七、方法 6：组合数学

## 思路

这个方法不再把问题看成一个 DP 问题，而是看成：

> 一共有多少种不同的移动顺序？

例如：

```
m = 3
n = 4
```

从左上到右下：

必须向下：

```
m - 1 = 2 次
```

必须向右：

```
n - 1 = 3 次
```

所以总共移动：

\[ (m-1)+(n-1)=m+n-2 \]

次。

对于 `3 x 4`：

```
总共 5 步：

D D R R R
```

现在问题变成：

> 5 个位置中选择 2 个位置放 `D`，有多少种选择？

因此：

\[ \binom{5}{2} \]

一般情况下：

\[ \boxed{ \binom{m+n-2}{m-1} } \]

或者：

\[ \boxed{ \binom{m+n-2}{n-1} } \]

两者完全相同。

根据组合数公式：

\[ \binom{N}{K} = \frac{N!}{K!(N-K)!} \]

因此：

\[ \text{answer} = \frac{(m+n-2)!} {(m-1)!(n-1)!} \]

------

## 代码：手动计算组合数

```
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # 如果只有一行或一列，只可能有一种走法
        if m == 1 or n == 1:
            return 1

        # 让 n 成为较小的维度，从而减少循环次数
        if m < n:
            m, n = n, m

        res = 1
        j = 1

        # 等价于计算 C(m+n-2, n-1)
        for i in range(m, m + n - 1):
            res *= i
            res //= j
            j += 1

        return res
```

例如：

```
m = 3
n = 4
```

交换之后：

```
m = 4
n = 3
```

循环计算：

\[ \frac{4}{1}\times\frac{5}{2}=10 \]

所以共有：

```
10
```

条不同路径。

## Python 中更直接的写法

Python 标准库 `math` 提供了：

```
math.comb(n, k)
```

用于直接计算组合数：

\[ \binom nk \]

因此 Python 中可以直接写：

```
from math import comb


class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # 总共 m+n-2 步，从中选择 m-1 步向下
        return comb(m + n - 2, m - 1)
```

### `math.comb`

例如：

```
from math import comb

print(comb(5, 2))
```

结果：

```
10
```

也就是：

\[ \binom 52 = 10 \]

Python 的整数本身支持任意精度，所以不像 C++/Java 那样容易因为普通整数类型范围不足而溢出。

## 复杂度

对于手动迭代版本：

- **时间复杂度：`O(min(m, n))`**
- **额外空间复杂度：`O(1)`**

从算法角度来看，这是本题最优雅的解法之一。

------

# 八、六种方法对比

| 方法         | 时间复杂度    | 空间复杂度 | 核心思想          |
| ------------ | ------------- | ---------- | ----------------- |
| 暴力递归     | `O(2^(m+n))`  | `O(m+n)`   | 枚举所有路径      |
| Top-Down DP  | `O(m*n)`      | `O(m*n)`   | DFS + Memoization |
| Bottom-Up DP | `O(m*n)`      | `O(m*n)`   | 二维状态转移      |
| 一维 DP      | `O(m*n)`      | `O(n)`     | 滚动数组          |
| 原地一维 DP  | `O(m*n)`      | `O(n)`     | 原地更新滚动数组  |
| 组合数学     | `O(min(m,n))` | `O(1)`     | 组合数            |

其中方法 4 和方法 5 本质上属于 **同一种 DP 空间优化思想**。区别只是方法 5 连 `newRow` 都省掉了。

# 九、常见错误

## 1. 把网格大小和移动次数混淆

`m x n` 网格并不意味着需要：

```
m 次向下
n 次向右
```

正确的是：

```
向下：m - 1 次
向右：n - 1 次
```

所以总移动次数：

\[ m+n-2 \]

这是组合数学解法中最常见的 off-by-one 错误。

------

## 2. 递归终止条件理解错误

原解析中认为下面这种写法一定错误：

```
if i == m - 1 or j == n - 1:
    return 1
```

这里需要稍微修正一下。

**对于这道没有障碍物、并且只能向右/向下走的题目，这个写法实际上也是正确的。**

因为一旦到达：

```
最后一行
```

就只能一直向右，因此恰好只有一条路径。

同理，到达：

```
最后一列
```

也只能一直向下。

因此可以写：

```
if i == m - 1 or j == n - 1:
    return 1
```

不过这种写法依赖于本题的特殊条件。如果题目变成 **有障碍物的网格**，就不能这么写。

更加通用的递归模板仍然是：

```
if i == m - 1 and j == n - 1:
    return 1

if i >= m or j >= n:
    return 0
```

------

## 3. 一维 DP 更新方向错误

状态转移：

```
dp[j] = dp[j] + dp[j + 1]
```

需要：

```
dp[j]     = 下方的旧值
dp[j + 1] = 右方的新值
```

因此必须：

```
for j in range(n - 2, -1, -1):
```

也就是 **从右向左** 更新。

这类问题在面试中非常重要：

> 把二维 DP 压缩成一维 DP 后，一定要重新分析更新顺序，否则可能覆盖后面仍然需要使用的旧状态。

------

## 4. 组合数学中的整数溢出

在 C++ / Java 等语言中，如果直接计算：

```
(m+n-2)!
---------
(m-1)!(n-1)!
```

中间的阶乘可能非常大，即使最终答案没有溢出，中间结果也可能先溢出。

所以更推荐：

```
边乘边除
```

而不是先计算完整阶乘。

Python 的：

```
int
```

支持任意精度整数，因此通常不需要担心普通整数溢出。

------

# 十、面试中的推荐思考路径

如果面试官要求你从基本方法逐渐优化，可以按照下面的逻辑展开：

```
暴力递归
    ↓
发现重复子问题
    ↓
Memoization
    ↓
Top-Down DP
    ↓
去掉递归
    ↓
Bottom-Up DP
    ↓
发现每一行只依赖下一行
    ↓
一维 DP / 滚动数组
    ↓
发现路径实际上只是 R 和 D 的排列
    ↓
组合数学
```

最核心的 DP 状态转移只有一个：

\[ \boxed{ dp[i][j]=dp[i+1][j]+dp[i][j+1] } \]

而组合数学的核心则是：

\[ \boxed{ \text{Unique Paths} = \binom{m+n-2}{m-1} = \binom{m+n-2}{n-1} } \]

如果这是现场代码面试，**一维 DP 通常是非常稳妥的主答案**：逻辑清晰、容易解释，时间 `O(mn)`，空间可以做到 `O(min(m,n))`。如果面试官继续追问能否更快，再给出组合数学解法，会是很自然的优化过程。
