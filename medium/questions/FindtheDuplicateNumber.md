# 寻找重复数（Find the Duplicate Number）

给定一个整数数组 `nums`，其中包含 `n + 1` 个整数，并且每个整数都位于 `[1, n]` 范围内。

数组中恰好有 **一个整数重复出现**，其他整数最多出现一次。

请返回这个重复的整数。

------

## 一、问题特点与面试重点

这道题有几个非常重要的条件：

- 数组长度为 `n + 1`
- 数值范围只有 `[1, n]`
- 一定存在重复数字
- 只有一种数字重复，但它可能出现两次或更多次

由于有 `n + 1` 个位置，却只有 `n` 种可能的数字，根据 **鸽巢原理（Pigeonhole Principle）**，一定至少存在一个重复数字。

这道题可以用很多方法解决，但如果题目进一步要求：

> **不能修改原数组，并且额外空间必须为 `O(1)`**

那么最经典、最值得掌握的方案就是：

**Floyd 快慢指针 / 环检测算法。**

下面按照从容易理解到更高级的顺序介绍各种方法。

------

# 1. 排序（Sorting）

## 思路

如果先对数组排序，相同的数字一定会排列在一起。

例如：

```
原数组：
[1, 3, 4, 2, 2]

排序后：
[1, 2, 2, 3, 4]
    ↑  ↑
```

因此排序后只需要扫描一次数组，比较相邻元素即可。

如果：

```
nums[i] == nums[i + 1]
```

那么这个数字就是重复数字。

## 算法

1. 对 `nums` 排序。
2. 从左到右扫描数组。
3. 比较相邻的两个元素。
4. 如果发现两个元素相同，立即返回该数字。

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # 原地排序
        nums.sort()

        # 检查相邻元素
        for i in range(len(nums) - 1):
            if nums[i] == nums[i + 1]:
                return nums[i]

        # 根据题目条件实际上不会执行到这里
        return -1
```

## Python：`list.sort()`

```
nums.sort()
```

会直接修改原数组，将数组原地排序。

例如：

```
nums = [3, 1, 2]
nums.sort()

print(nums)
# [1, 2, 3]
```

需要特别注意：

```
nums.sort()
```

与：

```
sorted(nums)
```

不同。

`sorted(nums)` 会创建一个新的排序结果，而不会修改原来的 `nums`。

## 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：取决于具体排序实现
- 会修改输入数组

### 总结

优点是非常直观。

缺点是：

- 排序增加了时间复杂度；
- `sort()` 会改变原数组；
- 如果面试要求 `O(1)` 额外空间且不能修改原数组，则不满足要求。

# 2. 哈希集合（Hash Set）

## 思路

在遍历数组时，可以记录所有已经出现过的数字。

对于当前数字 `num`：

- 如果之前没出现过，就加入集合；
- 如果已经在集合中，就说明它是重复数字。

例如：

```
nums = [1, 3, 4, 2, 2]

seen = {}

1 → 没出现 → 加入
3 → 没出现 → 加入
4 → 没出现 → 加入
2 → 没出现 → 加入
2 → 已经出现 → 找到答案
```

## 算法

1. 创建一个空集合 `seen`。
2. 遍历数组。
3. 如果 `num in seen`，直接返回 `num`。
4. 否则执行 `seen.add(num)`。

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        seen = set()

        for num in nums:
            # 如果已经出现过，说明 num 就是重复数字
            if num in seen:
                return num

            # 记录当前数字
            seen.add(num)

        return -1
```

## Python：`set`

`set` 是 Python 中的哈希集合。

例如：

```
seen = set()

seen.add(3)
seen.add(5)

print(3 in seen)
# True

print(4 in seen)
# False
```

平均情况下：

```
num in seen
```

以及：

```
seen.add(num)
```

时间复杂度都可以认为是：

```
O(1)
```

因此哈希集合非常适合处理：

> “某个元素是否曾经出现过？”

这种问题。

## 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 总结

这是实际写代码时最简单、最不容易出错的方法之一。

但缺点是需要额外 `O(n)` 空间，因此如果面试官要求：

```
O(1) extra space
```

就不能使用这个方法。

# 3. 辅助数组（Array as Seen Table）

## 思路

由于数字范围已经确定为：

```
1 ~ n
```

因此其实没有必要使用哈希表。

我们可以直接创建一个数组：

```
seen
```

然后让：

```
数字 1 → seen[0]
数字 2 → seen[1]
数字 3 → seen[2]
...
数字 n → seen[n - 1]
```

也就是：

```
index = num - 1
```

如果对应位置已经被标记，就说明这个数字曾经出现过。

## 算法

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # nums 长度为 n + 1，因此真正的数值范围为 1 ~ n
        n = len(nums) - 1

        # seen[i] 表示数字 i + 1 是否出现过
        seen = [0] * n

        for num in nums:
            idx = num - 1

            # 已经出现过
            if seen[idx]:
                return num

            # 标记为出现过
            seen[idx] = 1

        return -1
```

## 为什么是 `num - 1`？

Python 数组下标从 `0` 开始，但是题目中的数字从 `1` 开始。

因此需要做一个映射：

```
value       index
1      →      0
2      →      1
3      →      2
...
n      →    n - 1
```

也就是：

```
idx = num - 1
```

这是这道题中一个非常常见的技巧：

> 当数组元素范围与数组索引范围相近时，可以考虑让“值”映射到“索引”。

## 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 与 Hash Set 的区别

二者本质上非常相似：

```
Hash Set
    ↓
记录某个数字是否出现过

Array
    ↓
记录某个数字是否出现过
```

只不过这里数字范围明确，因此可以直接利用数组索引代替哈希。

# 4. 负数标记法（Negative Marking）

## 思路

上一种方法创建了一个额外的：

```
seen
```

数组。

但实际上，原数组本身就有足够的空间来记录：

> 某个数字是否出现过。

由于所有数字原本都是正数，我们可以利用：

```
正数 / 负数
```

作为两个状态。

看到数字 `num` 时，计算：

```
idx = abs(num) - 1
```

然后查看：

```
nums[idx]
```

如果它仍然是正数：

```
第一次看到 num
```

于是将它变成负数。

如果它已经是负数：

```
之前已经看到过 num
```

因此 `num` 就是重复数字。

## 示例

```
nums = [1, 3, 4, 2, 2]
```

看到 `1`：

```
idx = 0

[-1, 3, 4, 2, 2]
```

看到 `3`：

```
idx = 2

[-1, 3, -4, 2, 2]
```

看到 `4`：

```
idx = 3

[-1, 3, -4, -2, 2]
```

看到 `2`：

```
idx = 1

[-1, -3, -4, -2, 2]
```

再次看到 `2`：

```
idx = 1

nums[1] < 0
```

所以重复数字是：

```
2
```

## 代码

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        for num in nums:
            # num 本身可能已经因为之前的操作变成负数
            # 所以必须使用 abs()
            idx = abs(num) - 1

            # 如果对应位置已经为负数，
            # 说明 abs(num) 之前已经出现过
            if nums[idx] < 0:
                return abs(num)

            # 第一次看到这个数字，将对应位置变成负数
            nums[idx] *= -1

        return -1
```

## Python：`abs()`

```
abs(x)
```

返回数字的绝对值。

例如：

```
abs(-5)
# 5

abs(5)
# 5
```

这里必须使用：

```
abs(num)
```

因为我们在算法运行过程中不断修改 `nums` 中数字的正负号。

## 复杂度

- 时间复杂度：`O(n)`
- 额外空间复杂度：`O(1)`

## 重要缺点

这个方法虽然空间复杂度很好，但是：

> **它修改了原数组。**

因此如果题目明确要求：

```
Do not modify nums.
```

这个方法不能使用。

# 5. 对值域进行二分查找（Binary Search on Value Range）

这是一个非常值得理解的方法。

这里的二分查找与普通二分查找不太一样：

> **我们不是对数组下标进行二分，而是对答案可能存在的数值范围 `[1, n]` 进行二分。**

------

## 核心思想：鸽巢原理

假设：

```
mid = 3
```

我们统计数组中：

```
<= 3
```

的数字有多少个。

正常情况下，`1 ~ 3` 只有：

```
1, 2, 3
```

三个不同数字。

所以如果没有重复：

```
<= 3 的数字数量最多应该是 3
```

但如果发现：

```
count > 3
```

那么按照鸽巢原理：

> `1 ~ 3` 中一定存在重复数字。

因此可以继续搜索左半部分。

反之，如果：

```
count <= mid
```

说明重复数字一定在：

```
[mid + 1, high]
```

------

## 示例

```
nums = [1, 3, 4, 2, 2]

搜索范围：
1 ~ 4
```

第一次：

```
mid = 2
```

统计：

```
<= 2 的数字：
1, 2, 2

count = 3
```

因为：

```
3 > 2
```

所以重复数字一定在：

```
[1, 2]
```

继续缩小范围，最终得到：

```
2
```

------

## 代码

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # nums 有 n + 1 个元素
        # 所以合法数字范围为 1 ~ n
        n = len(nums) - 1

        low, high = 1, n

        while low < high:
            mid = low + (high - low) // 2

            # 统计 <= mid 的数字数量
            count = sum(1 for num in nums if num <= mid)

            # 如果数量超过 mid，
            # 根据鸽巢原理，重复数字位于左半部分
            if count > mid:
                high = mid
            else:
                # 否则重复数字位于右半部分
                low = mid + 1

        return low
```

## Python：生成器表达式与 `sum()`

这里：

```
sum(1 for num in nums if num <= mid)
```

相当于：

```
count = 0

for num in nums:
    if num <= mid:
        count += 1
```

表达式：

```
1 for num in nums if num <= mid
```

会针对每个满足条件的数字产生一个 `1`。

然后：

```
sum(...)
```

把这些 `1` 加起来，因此得到满足条件的元素个数。

------

## 为什么不能写成普通二分搜索？

普通二分搜索通常需要：

```
有序数组
```

但是这里数组没有排序。

我们利用的不是数组的有序性，而是：

```
count(x) = 数组中 <= x 的元素数量
```

这个统计条件产生的单调性质。

这是一个非常重要的算法思想：

> **Binary Search on Answer（对答案空间进行二分）**

它不仅出现在这道题中，在很多面试题中都非常常见。

## 复杂度

每次二分都需要完整扫描一次数组：

```
O(n)
```

值域大小为 `n`，需要：

```
O(log n)
```

次二分。

因此：

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(1)`
- 不修改原数组

------

# 6. 位运算（Bit Manipulation）

## 思路

可以从二进制的角度寻找重复数字。

例如数字：

```
1 = 001
2 = 010
3 = 011
4 = 100
```

分别统计每一个二进制位上：

```
nums 中有多少数字该位为 1
```

然后与正常情况下：

```
1 ~ n
```

这些数字中该位为 `1` 的数量进行比较。

如果某一位在 `nums` 中出现次数更多，那么重复数字在这一位上应该为 `1`。

最后把这些位组合起来，就可以恢复重复数字。

------

## 代码

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # 数字范围是 1 ~ n
        n = len(nums) - 1

        result = 0

        # Python 整数没有固定 32 位限制，
        # 这里使用 n.bit_length() 更自然
        for bit in range(n.bit_length()):
            mask = 1 << bit

            nums_count = 0
            normal_count = 0

            # nums 中这一位为 1 的数字数量
            for num in nums:
                if num & mask:
                    nums_count += 1

            # 正常的 1 ~ n 中这一位为 1 的数字数量
            for num in range(1, n + 1):
                if num & mask:
                    normal_count += 1

            # 多出来的 bit 来自重复数字
            if nums_count > normal_count:
                result |= mask

        return result
```

------

## Python 位运算说明

### `1 << bit`

这是左移操作。

例如：

```
1 << 0
# 0001

1 << 1
# 0010

1 << 2
# 0100

1 << 3
# 1000
```

因此：

```
mask = 1 << bit
```

可以创建一个只有目标 bit 为 `1` 的掩码。

------

### `num & mask`

`&` 是按位 AND。

例如：

```
num  = 6 = 110
mask = 2 = 010

110
010
---
010
```

结果非零，因此说明这一位是 `1`。

所以：

```
if num & mask:
```

可以判断：

> `num` 的第 `bit` 位是否为 `1`。

------

### `result |= mask`

`|` 是按位 OR。

例如：

```
result = 001
mask   = 010

001
010
---
011
```

因此：

```
result |= mask
```

相当于把这个 bit 设置为 `1`。

------

### `int.bit_length()`

例如：

```
8.bit_length()
# 4
```

因为：

```
8 = 1000
```

需要 4 个二进制位表示。

相比固定：

```
range(32)
```

使用：

```
range(n.bit_length())
```

更加符合 Python 的特点，因为 Python 的整数并不是固定 32 位整数。

## 复杂度

如果把整数位数视为固定常数：

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

更加严格地写：

```
O(n log n)
```

其中 `log n` 来自需要处理的二进制位数量。

### 面试角度

这种方法可以展示对位运算的理解，但代码和证明都比 Floyd 算法复杂。

一般不是这道题最值得优先选择的方法。

------

# 7. Floyd 快慢指针 / 环检测算法

这是本题最重要的方法。

如果题目要求：

- 不修改数组；
- `O(1)` 额外空间；
- `O(n)` 时间复杂度；

那么 Floyd 快慢指针基本就是标准答案。

------

## 核心思想：把数组看成链表

数组中的：

```
nums[i]
```

可以被理解为：

> 从节点 `i` 指向节点 `nums[i]`。

也就是说：

```
i → nums[i]
```

例如：

```
nums = [1, 3, 4, 2, 2]
```

可以构造：

```
0 → 1
1 → 3
3 → 2
2 → 4
4 → 2
```

因此：

```
0 → 1 → 3 → 2 → 4
              ↑   ↓
              ← ← ←
```

出现了一个环。

------

## 为什么重复数字会产生环？

假设重复数字是：

```
2
```

这意味着至少两个位置的值都是 `2`：

```
nums[a] = 2
nums[b] = 2
```

因此：

```
a ──→ 2
b ──→ 2
```

多个节点指向同一个节点。

结合：

```
n + 1 个节点
```

和：

```
值只能在 1 ~ n
```

这个特殊结构，最终一定会产生环。

而：

> **环的入口就是重复数字。**

因此问题就变成了经典的：

> 找链表环入口。

------

# Floyd 算法第一阶段：找到环内相遇点

定义两个指针：

```
slow
fast
```

其中：

```
slow 每次走一步
fast 每次走两步
```

也就是：

```
slow = nums[slow]
fast = nums[nums[fast]]
```

只要存在环，二者最终一定会在环中相遇。

```
slow = fast = 0

while True:
    slow = nums[slow]
    fast = nums[nums[fast]]

    if slow == fast:
        break
```

需要特别注意：

> **第一次相遇的位置通常不是重复数字。**

它只是环中的某个节点。

------

# Floyd 算法第二阶段：寻找环入口

第一次相遇后，再创建一个从起点出发的指针。

```
finder = 0
```

然后让：

```
slow 每次走一步
finder 每次走一步
```

即：

```
slow = nums[slow]
finder = nums[finder]
```

当：

```
slow == finder
```

时，这个位置就是环入口。

而环入口恰好对应重复数字。

------

## 完整代码

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # ---------- 第一阶段 ----------
        # 找到 slow 和 fast 在环中的第一次相遇点

        slow = 0
        fast = 0

        while True:
            # 慢指针每次走一步
            slow = nums[slow]

            # 快指针每次走两步
            fast = nums[nums[fast]]

            if slow == fast:
                break

        # ---------- 第二阶段 ----------
        # 从起点重新放置一个指针
        finder = 0

        while slow != finder:
            # 两个指针都每次走一步
            slow = nums[slow]
            finder = nums[finder]

        # 第二次相遇点就是环入口，
        # 也就是重复数字
        return slow
```

------

# 为什么第二次相遇一定在环入口？

这是 Floyd 算法最容易被问到的地方。

假设：

```
起点到环入口距离 = a
环入口到第一次相遇点距离 = b
环长度 = c
```

第一次相遇时：

```
slow 走过的距离 = a + b
```

fast 的速度是 slow 的两倍，因此：

```
fast 走过的距离 = 2(a + b)
```

与此同时，fast 比 slow 多跑了整数圈：

```
2(a + b) = a + b + kc
```

整理：

```
a + b = kc
```

所以：

```
a = kc - b
```

而：

```
c - b
```

就是从第一次相遇点走到环入口的距离。

因此：

```
a ≡ c - b (mod c)
```

也就是说：

> 从数组起点出发走 `a` 步，与从第一次相遇点继续走 `a` 步，会同时到达环入口。

所以第二阶段让两个指针：

```
一个从 0 出发
一个从第一次相遇点出发
```

并且都每次走一步，它们最终一定会在环入口相遇。

------

## 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`
- 不修改原数组

这正好满足本题最严格的要求。

------

| -------------- | ------------- | -------------- | ---------- | -------- |

| 辅助数组       | `O(n)`        | `O(n)`         | 否         | ⭐⭐       |
| 负数标记       | `O(n)`        | `O(1)`         | **是**     | ⭐⭐⭐      |
| 值域二分       | `O(n log n)`  | `O(1)`         | 否         | ⭐⭐⭐⭐     |
| 位运算         | `O(n log n)`* | `O(1)`         | 否         | ⭐⭐       |
| Floyd 快慢指针 | **`O(n)`**    | **`O(1)`**     | **否**     | ⭐⭐⭐⭐⭐    |

\* 如果整数位数被视为固定常数，也经常写作 `O(n)`。

# 常见错误

## 1. 没有检查是否允许修改原数组

例如：

```
nums.sort()
```

以及负数标记：

```
nums[idx] *= -1
```

都会修改输入数组。

如果题目明确要求：

```
You must not modify nums.
```

那么这两个方法都不合法。

因此面试时看到题目后，应该优先检查：

```
Can I modify the input?
```

------

## 2. Value → Index 映射时出现 Off-by-One Error

数字范围是：

```
1 ~ n
```

数组索引是：

```
0 ~ n - 1
```

因此通常需要：

```
idx = num - 1
```

而不是：

```
idx = num
```

例如：

```
num = n
```

应该映射到：

```
index = n - 1
```

如果直接访问：

```
nums[n]
```

可能造成越界或错误结果。

------

## 3. 认为 Floyd 第一次相遇点就是答案

这是快慢指针方案最常见的错误。

第一阶段：

```
slow == fast
```

只能说明：

> 两个指针已经在环中相遇。

这个位置不一定是环入口。

必须进行第二阶段：

```
finder = 0

while slow != finder:
    slow = nums[slow]
    finder = nums[finder]
```

第二次相遇的位置才是：

```
环入口 = duplicate
```

------

## 4. 混淆普通二分查找和值域二分

这里的 Binary Search 并不是：

```
nums[mid]
```

与某个 target 比较。

数组本身甚至完全不需要有序。

我们搜索的是：

```
答案所在的数值范围
```

通过：

```
count = number of values <= mid
```

判断重复数字在哪一侧。

这是典型的：

```
Binary Search on Answer
```

面试中应该能够清楚地区分这两种二分思想。

------

# 面试建议：最值得掌握的三个方案

如果时间有限，这道题不需要把七种方法全部背下来。最值得掌握的是下面三个。

### Hash Set

```
seen = set()

for num in nums:
    if num in seen:
        return num
    seen.add(num)
```

适合作为最直观的 `O(n)` 解法。

核心思想：

```
空间换时间
```

------

### 值域二分 + 鸽巢原理

核心判断：

```
count = sum(num <= mid for num in nums)

if count > mid:
    high = mid
else:
    low = mid + 1
```

它非常适合展示：

```
Pigeonhole Principle
+
Binary Search on Answer
```

这两个重要算法思想。

------

### Floyd 快慢指针

最终最优方案：

```
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        slow = fast = 0

        # Phase 1: 找到环内相遇点
        while True:
            slow = nums[slow]
            fast = nums[nums[fast]]

            if slow == fast:
                break

        # Phase 2: 找到环入口
        finder = 0

        while finder != slow:
            finder = nums[finder]
            slow = nums[slow]

        return slow
```

满足：

```
Time:  O(n)
Space: O(1)
```

同时：

```
不排序
不修改数组
不使用额外数据结构
```

因此，这是本题最推荐的面试答案。

# 核心知识总结

这道题真正值得掌握的并不只是“找重复数字”，而是几个可以迁移到其他算法题的重要思想：

```
1. Hash Set
   → 快速判断元素是否曾经出现

2. Value → Index Mapping
   → 当数值范围和数组下标范围接近时，
     可以考虑利用数组本身进行状态记录

3. In-place Marking
   → 利用正负号等状态编码信息，降低空间复杂度

4. Pigeonhole Principle
   → n + 1 个元素放入 n 个可能的位置，
     必然存在重复

5. Binary Search on Answer
   → 不一定要在有序数组上二分，
     只要答案空间具有可以判断方向的单调性质，就可能二分

6. Floyd Cycle Detection
   → 数组中的值可以被解释为“下一个节点”
   → 数组问题可以转化为隐式链表问题

7. Bit Manipulation
   → 可以通过逐 bit 统计与重建数字
```

对于代码面试而言，这道题最关键的一步通常是意识到：

> **`nums[i]` 不仅可以被看成一个“数值”，还可以被看成“下一个索引”。**

一旦完成这个视角转换，问题就从“数组中寻找重复值”变成了：

> **在一个隐式链表中寻找环的入口。**

这正是 Floyd 快慢指针能够解决本题的根本原因。
