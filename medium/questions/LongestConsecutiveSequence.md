# 最长连续序列（Longest Consecutive Sequence）

给定一个整数数组 `nums`，返回其中能够组成的**最长连续序列的长度**。

所谓连续序列，是指序列中的后一个元素恰好比前一个元素大 `1`。

需要注意：

- 这些元素**不要求在原数组中相邻**
- 只要求它们的数值能够构成连续整数
- 题目要求最终算法的时间复杂度为 **`O(n)`**

------

## 示例 1

```text
Input: nums = [2,20,4,10,3,4,5]

Output: 4
```

最长连续序列为：

```text
[2, 3, 4, 5]
```

所以答案是：

```text
4
```

------

## 示例 2

```text
Input: nums = [0,3,2,5,4,6,1,1]

Output: 7
```

可以组成：

```text
[0, 1, 2, 3, 4, 5, 6]
```

因此最长长度为：

```text
7
```

注意原数组中虽然有两个 `1`，但重复元素不会增加连续序列的长度。

------

# 1. 暴力解法

## 思路

最直接的想法是：

> 对数组中的每一个数字，都把它当作连续序列的起点，然后不断寻找 `num + 1`、`num + 2`、`num + 3`……

为了快速判断某个数字是否存在，我们先把所有数字放进 `set`。

例如：

```text
nums = [2,20,4,10,3,4,5]
```

转换成集合：

```text
{2, 3, 4, 5, 10, 20}
```

如果从 `2` 开始：

```text
2 存在
3 存在
4 存在
5 存在
6 不存在
```

所以得到长度：

```text
4
```

这个方法是正确的，但存在大量**重复计算**。

例如如果已经从 `2` 检查了：

```text
2 -> 3 -> 4 -> 5
```

之后再从 `3` 开始时，还会重复检查：

```text
3 -> 4 -> 5
```

从 `4` 又会检查：

```text
4 -> 5
```

因此效率比较低。

------

## 算法步骤

1. 将 `nums` 转换成集合 `store`
2. 初始化答案：

```python
res = 0
```

1. 对数组中的每个 `num`：
   - 将它当作某个连续序列的起点
   - `curr = num`
   - 不断检查 `curr` 是否存在于集合中
   - 如果存在：
     - 当前长度 `streak += 1`
     - `curr += 1`
2. 更新最长长度
3. 返回 `res`

------

## Python 中的 `set`

这里使用：

```python
store = set(nums)
```

Python 的 `set` 是基于**哈希表（Hash Table）**实现的数据结构。

它最重要的特性之一是：

```python
x in store
```

平均时间复杂度为：

```text
O(1)
```

例如：

```python
store = {2, 3, 4, 5}

3 in store   # True
8 in store   # False
```

这也是为什么这里不能直接使用：

```python
curr in nums
```

因为在 Python 的 `list` 中查找一个元素通常需要：

```text
O(n)
```

而 `set` 平均只需要：

```text
O(1)
```

------

## 代码

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        # 保存目前找到的最长连续序列长度
        res = 0

        # 转换成 set，使 membership 查询平均为 O(1)
        store = set(nums)

        # 尝试把每一个数字都当作连续序列的起点
        for num in nums:
            streak = 0
            curr = num

            # 不断寻找 curr, curr + 1, curr + 2 ...
            while curr in store:
                streak += 1
                curr += 1

            # 更新最长长度
            res = max(res, streak)

        return res
```

------

## 复杂度分析

### 时间复杂度

最坏情况下：

```text
O(n²)
```

虽然：

```python
curr in store
```

平均是 `O(1)`，但问题在于我们会从很多不同的位置重复扫描同一个连续序列。

例如：

```text
nums = [1, 2, 3, 4, 5]
```

会进行：

```text
从 1 开始：检查 1,2,3,4,5
从 2 开始：检查 2,3,4,5
从 3 开始：检查 3,4,5
从 4 开始：检查 4,5
从 5 开始：检查 5
```

总工作量：

```text
5 + 4 + 3 + 2 + 1
```

也就是：

```text
O(n²)
```

### 空间复杂度

```text
O(n)
```

因为需要一个 `set` 保存数组中的元素。

------

# 2. 排序解法

## 思路

如果先把数组排序，那么所有连续数字就会自然地排在一起。

例如：

```text
nums = [2,20,4,10,3,4,5]
```

排序后：

```text
[2,3,4,4,5,10,20]
```

这时连续序列：

```text
2,3,4,5
```

就很容易被识别出来。

需要特别处理两种情况：

### 情况 1：当前数字比前一个大 1

说明连续序列继续：

```text
2 -> 3 -> 4
```

### 情况 2：当前数字和前一个相同

说明遇到重复数字：

```text
2 -> 3 -> 4 -> 4 -> 5
```

重复的 `4` 不应该：

- 增加序列长度
- 也不应该中断序列

所以应该直接跳过。

### 情况 3：差值大于 1

例如：

```text
2 -> 3 -> 4 -> 10
```

说明原来的连续序列结束，需要重新开始计数。

------

# 更直观的排序写法

原答案的写法是正确的，但可以用一种更适合面试表达的方式来实现：

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        if not nums:
            return 0

        # 排序后，相邻的连续数字会排列在一起
        nums.sort()

        # 当前连续序列长度
        streak = 1

        # 最长连续序列长度
        res = 1

        for i in range(1, len(nums)):
            # 情况 1：重复元素，不影响连续序列
            if nums[i] == nums[i - 1]:
                continue

            # 情况 2：刚好大 1，连续序列继续
            if nums[i] == nums[i - 1] + 1:
                streak += 1

            # 情况 3：出现断层，重新开始
            else:
                streak = 1

            res = max(res, streak)

        return res
```

这个版本通常比原答案更容易解释和维护。

------

## 算法步骤

1. 如果数组为空，返回 `0`
2. 对数组排序
3. 初始化：

```python
streak = 1
res = 1
```

1. 从第二个元素开始遍历
2. 比较：

```python
nums[i]
```

和：

```python
nums[i - 1]
```

有三种可能：

```text
相等        -> 跳过重复元素
刚好大 1   -> streak += 1
大于 1     -> streak = 1
```

1. 不断更新 `res`

------

## 复杂度分析

### 时间复杂度

排序本身需要：

```text
O(n log n)
```

之后线性扫描：

```text
O(n)
```

因此总时间复杂度为：

```text
O(n log n)
```

### 空间复杂度

通常写成：

```text
O(1) ~ O(n)
```

具体取决于排序算法以及语言实现。

Python 的：

```python
nums.sort()
```

使用的是 **Timsort**，排序过程中可能需要额外辅助空间，因此严格来说不能简单认为始终是 `O(1)`。

# 3. 哈希集合解法：O(n)

这是这道题最重要的解法，也是最符合题目要求的解法。

题目明确要求：

```text
O(n)
```

因此排序解法虽然正确，但并不是最终最优答案。

------

## 核心思路

暴力解法效率低的原因是：

> 它从连续序列中的每一个数字都重新向后搜索。

例如：

```text
1, 2, 3, 4, 5
```

暴力解法会分别从：

```text
1
2
3
4
5
```

开始搜索。

但实际上：

```text
2
```

根本没有必要作为起点，因为：

```text
1
```

已经存在。

同理：

```text
3
```

也不是起点，因为：

```text
2
```

存在。

因此一个关键观察是：

> **只有当 `num - 1` 不存在时，`num` 才可能是一个连续序列的起点。**

------

## 如何判断序列起点

假设集合中存在：

```text
{1, 2, 3, 4, 100, 200}
```

对于：

```text
1
```

检查：

```text
0 是否存在？
```

不存在，因此：

```text
1
```

是一个序列起点。

然后从它开始：

```text
1 -> 2 -> 3 -> 4
```

对于：

```text
2
```

检查：

```text
1 是否存在？
```

存在，所以：

```text
2
```

一定不是起点。

因此直接跳过，不进行任何向后搜索。

------

## 算法步骤

1. 将所有数字放进集合：

```python
num_set = set(nums)
```

1. 遍历集合中的每个数字 `num`
2. 判断：

```python
if num - 1 not in num_set:
```

如果成立，则说明：

```text
num
```

是某个连续序列的起点。

1. 从 `num` 开始不断寻找：

```text
num + 1
num + 2
num + 3
...
```

1. 统计长度
2. 更新最大值

------

## 最优代码

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        # 用 set 去重，同时支持平均 O(1) 查询
        num_set = set(nums)

        # 保存最长连续序列长度
        longest = 0

        # 遍历 set 而不是原数组，可以避免重复数字带来的重复处理
        for num in num_set:

            # 只有 num - 1 不存在时，
            # num 才是某个连续序列的起点
            if num - 1 not in num_set:

                current = num
                streak = 1

                # 从起点向后寻找连续数字
                while current + 1 in num_set:
                    current += 1
                    streak += 1

                # 更新最长长度
                longest = max(longest, streak)

        return longest
```

------

# 为什么这个解法是 O(n)？

第一次看到这里很容易产生疑问：

> 外层有 `for`，里面又有 `while`，为什么不是 `O(n²)`？

关键在于：

```python
while
```

只会从**真正的序列起点**开始执行。

例如：

```text
nums = [1,2,3,4,5]
```

外层会检查：

```text
1
2
3
4
5
```

但只有：

```text
1
```

满足：

```python
1 - 1 not in num_set
```

所以只有 `1` 会真正进入完整的 `while`：

```text
1 -> 2 -> 3 -> 4 -> 5
```

而：

```text
2,3,4,5
```

都不会再重复扫描这个序列。

因此每个数字最多被：

- 外层检查一次
- 在某个连续序列中访问一次

总工作量与 `n` 成正比。

所以平均时间复杂度为：

```text
O(n)
```

# 三种解法对比

| 解法                | 时间复杂度   | 空间复杂度     | 是否满足题目 `O(n)` |
| ------------------- | ------------ | -------------- | ------------------- |
| 暴力搜索            | `O(n²)`      | `O(n)`         | ❌                   |
| 排序                | `O(n log n)` | 取决于排序实现 | ❌                   |
| Hash Set + 起点判断 | `O(n)` 平均  | `O(n)`         | ✅                   |

# 常见错误

## 1. 从每个数字都开始向后搜索

错误思路：

```python
for num in nums:
    curr = num

    while curr in num_set:
        curr += 1
```

虽然用了 `set`，但依然存在大量重复搜索，最坏情况下是：

```text
O(n²)
```

真正的优化点并不是“使用 `set`”本身，而是：

```python
if num - 1 not in num_set:
```

只从序列起点开始扫描。

------

## 2. 把 `num + 1` 不存在作为起点条件

错误：

```python
if num + 1 not in num_set:
```

这判断的是：

> `num` 是否是一个连续序列的**终点**

而不是起点。

如果我们希望从小到大向后搜索，就应该检查：

```python
num - 1 not in num_set
```

------

## 3. 忘记重复元素

例如：

```text
nums = [1,2,2,3]
```

最长连续序列应该是：

```text
1,2,3
```

长度：

```text
3
```

而不是 `4`。

使用：

```python
set(nums)
```

会自然去重：

```text
{1,2,3}
```

因此 Hash Set 解法天然能够正确处理重复元素。

------

## 4. 空数组

题目允许：

```text
nums.length = 0
```

最优解中：

```python
num_set = set(nums)
longest = 0
```

如果集合为空，循环不会执行，直接返回：

```text
0
```

所以不需要额外写：

```python
if not nums:
    return 0
```

当然写上也没有问题。

------

# 面试中的核心总结

这道题最重要的并不是使用 `set`，而是找到：

> **如何避免重复搜索同一个连续序列。**

关键判断：

```python
if num - 1 not in num_set:
```

含义是：

> 如果比 `num` 小 1 的数字不存在，那么 `num` 一定是某个连续序列的第一个数字。

然后只从这里开始：

```python
while current + 1 in num_set:
```

向后扩展。

整个最优解可以浓缩成：

```python
num_set = set(nums)

for num in num_set:
    if num - 1 not in num_set:
        # num 是连续序列的起点
        ...
```

在面试中可以这样解释：

> “我会先把所有数字放入哈希集合，使查询平均为 `O(1)`。为了避免从连续序列中的每个数字重复向后搜索，我只在 `num - 1` 不存在时把 `num` 当作序列起点。然后不断检查 `num + 1`、`num + 2` 等数字是否存在。这样每个数字只会被有效遍历常数次，因此整体平均时间复杂度是 `O(n)`，空间复杂度是 `O(n)`。”
