# Jump Game II（跳跃游戏 II）

## 题目描述

给定一个整数数组 `nums`，其中 `nums[i]` 表示从索引 `i` 出发，**向右最多可以跳跃的距离**。

例如，当我们位于索引 `i` 时，可以跳到任意索引 `i + j`，其中：

- `j <= nums[i]`
- `i + j < len(nums)`

初始位置为索引 `0`。

请返回到达数组最后一个位置（索引 `len(nums) - 1`）所需要的**最少跳跃次数**。

题目保证一定存在一种方案可以到达最后一个位置。

------

# 一、递归 / 暴力搜索

## 核心思路

最直接的想法是：

> 从当前位置出发，把所有可能的下一跳都尝试一遍，然后选择总跳跃次数最少的方案。

假设当前位于索引 `i`，那么最多可以向右跳 `nums[i]` 步，因此下一步可以选择：

```
i + 1
i + 2
...
i + nums[i]
```

当然，不能超过数组最后一个索引。

我们可以定义：

```
dfs(i)
```

表示：

> **从索引 `i` 出发，到达最后一个索引最少需要多少次跳跃？**

那么状态转移可以写成：

\[ dfs(i) = 1 + \min(dfs(j)) \]

其中 `j` 是从 `i` 能够直接跳到的所有位置。

### 递归终止条件

有两个重要的终止情况：

1. **已经到达最后一个位置**

   不需要继续跳：

   ```
   return 0
   ```

2. **`nums[i] == 0`**

   当前无法继续向右跳，这条路径无法到达终点，因此可以返回正无穷：

   ```
   return float("inf")
   ```

------

## 算法步骤

1. 定义递归函数 `dfs(i)`，表示从索引 `i` 到终点需要的最少跳跃次数。

2. 如果 `i` 已经是最后一个索引，返回 `0`。

3. 如果 `nums[i] == 0`，说明无法继续前进，返回正无穷。

4. 计算当前位置最远能够跳到的位置：

   ```
   end = min(len(nums) - 1, i + nums[i])
   ```

5. 枚举 `[i + 1, end]` 中的所有下一跳位置 `j`。

6. 对每个 `j`，当前这一步消耗一次跳跃，因此答案为：

   ```
   1 + dfs(j)
   ```

7. 取所有选择中的最小值。

8. 最终返回 `dfs(0)`。

------

## 代码

```
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:

        def dfs(i: int) -> int:
            # 已经到达最后一个位置，不需要继续跳
            if i == len(nums) - 1:
                return 0

            # 当前无法继续向右跳，这条路径无效
            if nums[i] == 0:
                return float("inf")

            # 当前能够到达的最远位置
            end = min(len(nums) - 1, i + nums[i])

            # 保存从当前位置到终点所需的最少跳跃次数
            res = float("inf")

            # 尝试所有可能的下一跳
            for j in range(i + 1, end + 1):
                res = min(res, 1 + dfs(j))

            return res

        return dfs(0)
```

### `float("inf")` 说明

Python 中：

```
float("inf")
```

表示**正无穷大**。

它非常适合这种“求最小值，但是某些路径无效”的场景。例如：

```
min(3, float("inf"))
# 3
```

因此，我们可以把无法到达终点的路径看成需要“无限多次跳跃”，这样它自然不会被 `min()` 选中。

------

## 复杂度分析

设数组长度为 `n`。

- **时间复杂度：指数级，最坏可达到 \(O(2^n)\)**
- **空间复杂度：\(O(n)\)**

原答案将时间复杂度写成了 `O(n!)`，但更准确地说，这种暴力递归的搜索树在最坏情况下具有**指数级**数量的路径。

例如，当每个位置都允许跳到后面的很多位置时，递归会反复计算：

```
dfs(3)
dfs(4)
dfs(5)
...
```

这正是接下来动态规划可以优化的地方。

------

# 二、Top-Down 动态规划：记忆化搜索

## 核心思路

暴力递归最大的问题不是递归本身，而是：

> **同一个状态会被重复计算很多次。**

例如：

```
dfs(0)
├── dfs(1)
│   └── dfs(3)
└── dfs(2)
    └── dfs(3)
```

这里 `dfs(3)` 被计算了两次。

但注意：

```
dfs(3)
```

无论是从 `1` 还是从 `2` 到达 `3`，它所表示的问题始终都是：

> 从索引 `3` 出发，到达终点最少需要多少步？

所以第一次计算 `dfs(3)` 后，可以把结果保存下来。

这就是 **Memoization（记忆化搜索）**。

------

## 状态定义

定义：

\[ memo[i] = \text{从索引 i 到达最后一个索引所需的最少跳跃次数} \]

当再次调用：

```
dfs(i)
```

时，如果 `i` 已经存在于 `memo` 中，就直接返回：

```
if i in memo:
    return memo[i]
```

这样每个索引的答案最多只需要真正计算一次。

------

## 算法步骤

1. 创建哈希表 `memo`。

2. 定义 `dfs(i)`。

3. 如果 `i` 已经计算过，直接返回 `memo[i]`。

4. 如果已经到达最后一个索引，返回 `0`。

5. 如果 `nums[i] == 0`，返回正无穷。

6. 枚举当前位置能够到达的所有下一跳位置。

7. 计算：

   \[ 1 + dfs(j) \]

8. 找出其中最小值。

9. 将结果保存到：

   ```
   memo[i]
   ```

10. 返回 `dfs(0)`。

------

## 代码

```
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:
        # memo[i]：
        # 从索引 i 出发，到达最后一个位置所需的最少跳跃次数
        memo = {}

        def dfs(i: int) -> int:
            # 已经计算过，直接复用结果
            if i in memo:
                return memo[i]

            # 已经到达终点
            if i == len(nums) - 1:
                return 0

            # 无法继续向右移动
            if nums[i] == 0:
                return float("inf")

            res = float("inf")

            # Python range 的右边界不包含在范围内
            # 所以这里使用 i + nums[i] + 1
            end = min(len(nums), i + nums[i] + 1)

            # 尝试所有可以直接跳到的位置
            for j in range(i + 1, end):
                res = min(res, 1 + dfs(j))

            # 保存当前状态的答案
            memo[i] = res

            return res

        return dfs(0)
```

------

## 为什么复杂度变成 \(O(n^2)\)？

一共有最多 `n` 个不同状态：

```
dfs(0)
dfs(1)
...
dfs(n - 1)
```

因为有 `memo`，每个状态只需要真正计算一次。

但是计算 `dfs(i)` 时，最坏情况下可能需要遍历后面的 `O(n)` 个位置。

因此：

\[ O(n) \times O(n) = O(n^2) \]

所以：

- **时间复杂度：\(O(n^2)\)**
- **空间复杂度：\(O(n)\)**

空间主要来自：

- `memo`：\(O(n)\)
- 递归调用栈：最坏 \(O(n)\)

总空间仍然是 \(O(n)\)。

------

# 三、Bottom-Up 动态规划

## 核心思路

Top-Down 的状态定义是：

\[ dfs(i) = \text{从 i 到终点的最少跳跃次数} \]

我们也可以直接创建一个数组：

```
dp[i]
```

表示：

> **从索引 `i` 出发，到达最后一个位置最少需要多少次跳跃。**

这和前面的 `dfs(i)` 本质上完全一样。

区别只是：

- Top-Down：递归，需要哪个状态就计算哪个状态
- Bottom-Up：按照确定的顺序主动计算所有状态

------

## 状态转移

最后一个位置显然不需要继续跳：

\[ dp[n-1] = 0 \]

对于任意位置 `i`：

```
i -> j -> 最后一个位置
```

如果第一步从 `i` 跳到 `j`：

- `i -> j` 消耗 `1` 次
- `j -> end` 消耗 `dp[j]` 次

所以：

\[ dp[i] = 1 + \min(dp[j]) \]

其中 `j` 是所有从 `i` 可以直接到达的位置。

------

## 为什么从右向左计算？

因为：

```
dp[i]
```

依赖：

```
dp[i + 1]
dp[i + 2]
...
```

也就是依赖**右侧的状态**。

因此应该先计算右边，再计算左边：

```
← ← ← ← ←
0 1 2 3 4
        ↑
      dp[4] = 0
```

------

## 代码

```
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:
        n = len(nums)

        # dp[i]：
        # 从索引 i 到达最后一个位置所需的最少跳跃次数
        dp = [float("inf")] * n

        # 已经在最后一个位置，不需要跳
        dp[n - 1] = 0

        # 从右向左计算
        for i in range(n - 2, -1, -1):

            # 当前可以跳到的位置为：
            # [i + 1, i + nums[i]]
            #
            # 由于 range 不包含右边界，所以需要 +1
            end = min(n, i + nums[i] + 1)

            for j in range(i + 1, end):
                dp[i] = min(dp[i], 1 + dp[j])

        return dp[0]
```

------

## 复杂度分析

每个位置 `i` 最坏可能检查 `O(n)` 个下一跳位置：

\[ O(n) \times O(n) = O(n^2) \]

因此：

- **时间复杂度：\(O(n^2)\)**
- **空间复杂度：\(O(n)\)**

------

# 四、BFS 思想 + 贪心 ⭐

这是本题最重要、也是代码面试中最值得掌握的解法。

## 核心思路

这道题要求的是：

> **最少跳跃次数**

看到“最少步数”，一个非常自然的思路就是 **BFS（广度优先搜索）**。

我们可以把数组中的索引看成图中的节点。

例如：

```
nums = [2, 3, 1, 1, 4]
```

从索引 `0` 可以跳到：

```
0
├── 1
└── 2
```

然后：

```
1 次跳跃：1, 2
2 次跳跃：3, 4, ...
```

BFS 的关键性质是：

> **第一次到达目标节点时，使用的层数就是最少步数。**

但是这里没有必要真的创建队列，因为每一层能够到达的位置实际上形成了一个连续区间。

所以我们可以使用两个变量：

```
l
r
```

表示当前 BFS 层：

```
[l, r]
```

------

## 如何理解 `[l, r]`？

假设：

```
nums = [2, 3, 1, 1, 4]
```

初始：

```
res = 0

[l, r] = [0, 0]
```

表示：

> 使用 `0` 次跳跃，可以到达索引 `0`。

### 第一层

检查索引 `0`：

```
0 + nums[0] = 2
```

所以再跳一次，可以到达：

```
[1, 2]
```

于是：

```
res = 1
[l, r] = [1, 2]
```

------

### 第二层

现在我们知道：

> 使用 `1` 次跳跃，可以到达 `[1, 2]` 中的所有位置。

检查这个区间中的所有位置：

```
i = 1:
1 + nums[1] = 4

i = 2:
2 + nums[2] = 3
```

因此再跳一次最远可以到：

```
4
```

下一层就是：

```
[3, 4]
```

此时：

```
res = 2
```

索引 `4` 已经是终点。

答案：

```
2
```

------

# 为什么这是贪心？

对于当前 BFS 层：

```
[l, r]
```

我们不关心具体选择哪个位置作为下一跳。

我们只关心：

> **从当前所有可达位置出发，下一跳最远能覆盖到哪里？**

因此：

```
farthest = max(farthest, i + nums[i])
```

这就是贪心的部分。

注意，这和“每次直接跳到当前能跳到的最远索引”是不同的。

这里的策略是：

> **先检查当前这一层的所有候选位置，再决定下一层最远能够覆盖到哪里。**

------

## 算法步骤

初始化：

```
res = 0
l = r = 0
```

其中：

- `res`：已经使用的跳跃次数
- `[l, r]`：使用 `res` 次跳跃能够到达的当前 BFS 层

然后：

1. 遍历当前区间 `[l, r]`。

2. 对每个位置 `i`，计算：

   ```
   i + nums[i]
   ```

3. 找到下一跳能够到达的最远位置：

   ```
   farthest
   ```

4. 当前 BFS 层处理完成后，下一层为：

   ```
   l = r + 1
   r = farthest
   ```

5. 跳跃次数增加：

   ```
   res += 1
   ```

6. 当 `r >= n - 1` 时，说明终点已经在当前可达范围中。

------

## 代码

```
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:
        # 已经使用的跳跃次数
        res = 0

        # [l, r] 表示当前 BFS 层的索引范围
        # 初始时 0 次跳跃只能到达索引 0
        l = r = 0

        # 当当前可达范围还没有覆盖最后一个位置时继续
        while r < len(nums) - 1:

            # 下一次跳跃能够到达的最远位置
            farthest = 0

            # 遍历当前 BFS 层的所有位置
            for i in range(l, r + 1):
                farthest = max(
                    farthest,
                    i + nums[i]
                )

            # 下一层从当前层之后的位置开始
            l = r + 1

            # 下一层最远可以到达 farthest
            r = farthest

            # 完成了一次跳跃
            res += 1

        return res
```

------

## 复杂度分析

虽然代码中存在：

```
while ...
    for ...
```

但它**不是 \(O(n^2)\)**。

因为每次更新：

```
l = r + 1
```

所以不同 BFS 层之间的区间不会重复。

例如：

```
[0]
[1, 2]
[3, 4, 5]
[6, 7]
```

每个索引最多被 `for` 循环访问一次。

因此：

- **时间复杂度：\(O(n)\)**
- **空间复杂度：\(O(1)\)**

这是本题的最优解法。

------

# 五、另一种常见的贪心写法

面试中也经常看到下面这种更加紧凑的实现：

```
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:
        jumps = 0

        # 当前 jumps 次跳跃能够覆盖到的最远边界
        current_end = 0

        # 在下一次跳跃之后能够到达的最远位置
        farthest = 0

        # 不需要处理最后一个位置，
        # 因为到达最后一个位置之后不需要继续跳
        for i in range(len(nums) - 1):

            # 不断扩大“下一跳”的最远覆盖范围
            farthest = max(farthest, i + nums[i])

            # 已经扫描完当前这一跳能够覆盖的所有位置
            if i == current_end:

                # 必须进行下一次跳跃
                jumps += 1

                # 更新新的覆盖边界
                current_end = farthest

        return jumps
```

它和前面的 `[l, r]` BFS 写法本质完全相同，只不过省略了显式的“层区间”。

可以这样对应理解：

```
BFS 写法                 紧凑贪心写法

[l, r] 当前层      <=>    current_end
farthest           <=>    farthest
res                <=>    jumps
```

如果第一次学习这道题，我更推荐先理解 `[l, r]` 版本，因为它能非常清楚地展示为什么这是一个 **BFS + Greedy** 问题。

# 六、常见错误

## 1. 每次直接跳到最远的位置

一个很常见的错误是：

> 当前位置 `i` 可以跳 `nums[i]` 步，所以直接跳到 `i + nums[i]`。

这种策略并不能保证跳跃次数最少。

例如：

```
当前位置
   ↓
   i
   ├── A
   ├── B
   └── C ← 当前能跳到的最远位置
```

虽然 `C` 是当前最远的位置，但可能：

```
C 下一步只能移动很短距离
```

而较近的 `B` 可能：

```
B 下一步能够直接跳得非常远
```

所以正确的贪心思想不是：

> **这一跳，我应该落在哪里最远？**

而是：

> **在当前这一跳能够到达的所有位置中，哪个位置能够让“下一跳”的覆盖范围最远？**

这两个概念非常容易混淆。

------

## 2. BFS 区间边界出现 Off-by-One Error

在 BFS + Greedy 解法中：

```
[l, r]
```

是一个**闭区间**。

因此遍历时应该：

```
for i in range(l, r + 1):
```

而不是：

```
for i in range(l, r):
```

因为 Python 的 `range()` 不包含右边界。

下一层应该从：

```
r + 1
```

开始：

```
l = r + 1
r = farthest
```

------

## 3. `range()` 的右边界

Python：

```
range(start, end)
```

实际产生的是：

```
start, start + 1, ..., end - 1
```

因此，如果我们希望枚举：

```
i + 1 ... i + nums[i]
```

需要写成：

```
range(i + 1, i + nums[i] + 1)
```

同时还需要避免越界，因此通常写成：

```
end = min(len(nums), i + nums[i] + 1)

for j in range(i + 1, end):
    ...
```

------

## 4. `nums[i] == 0`

对于递归和 DP：

```
nums[i] == 0
```

意味着从当前位置无法继续前进。

因此可以将这个状态视为：

```
float("inf")
```

表示无法通过这条路径到达终点。

不过对于最优的 BFS + Greedy 解法，由于题目已经保证：

> 一定可以到达最后一个位置。

所以通常不需要额外处理无法到达终点的情况。

------

# 七、四种方法对比

| 方法         | 核心思想                   | 时间复杂度   | 空间复杂度   | 面试推荐度 |
| ------------ | -------------------------- | ------------ | ------------ | ---------- |
| 暴力递归     | 枚举所有跳跃方案           | 指数级       | \(O(n)\)     | ★          |
| Top-Down DP  | 递归 + Memoization         | \(O(n^2)\)   | \(O(n)\)     | ★★★        |
| Bottom-Up DP | 从右向左计算 DP            | \(O(n^2)\)   | \(O(n)\)     | ★★★        |
| BFS + Greedy | 按跳跃次数分层扩展覆盖范围 | **\(O(n)\)** | **\(O(1)\)** | ★★★★★      |

------

# 八、面试中最重要的思维过程

这道题最值得掌握的并不是记住最终的 `O(n)` 代码，而是理解下面这条优化路径：

```
暴力递归
    ↓
发现相同 dfs(i) 被重复计算
    ↓
Memoization / Top-Down DP
    ↓
去掉递归
    ↓
Bottom-Up DP
    ↓
发现题目求“最少跳跃次数”
    ↓
联想到 BFS 的最短路径 / 最少步数
    ↓
发现每一层都是连续的索引区间
    ↓
不需要真正使用 Queue
    ↓
使用 [l, r] 表示 BFS 层
    ↓
每层只维护 farthest
    ↓
BFS + Greedy
    ↓
O(n) 时间 + O(1) 空间
```

尤其需要记住 BFS + Greedy 中三个变量的含义：

```
l, r
# 当前跳跃次数能够到达的索引范围

farthest
# 再跳一次能够到达的最远位置

res
# 已经进行的跳跃次数
```

一旦理解：
