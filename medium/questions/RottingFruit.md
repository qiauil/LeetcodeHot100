# Rotting Fruit（腐烂的水果）

给定一个二维矩阵 `grid`，其中每个单元格可能有以下三种取值：

- `0`：空单元格
- `1`：新鲜水果
- `2`：腐烂水果

每经过 **1 分钟**，如果一个新鲜水果在水平方向或垂直方向上与腐烂水果相邻，那么这个新鲜水果也会腐烂。

返回直到矩阵中 **不存在新鲜水果** 所需要经过的最少分钟数。

如果无论经过多少时间，都无法让所有新鲜水果腐烂，则返回 `-1`。

------

## 1. 多源广度优先搜索 BFS

### 核心思路

这是一道非常典型的 **多源 BFS（Multi-source BFS）** 问题。

普通 BFS 往往从一个起点开始扩散，而这道题中，所有初始的腐烂水果都会在同一时刻向周围传播，因此需要把 **所有腐烂水果同时作为 BFS 的起点**。

可以把 BFS 的每一层理解为一分钟：

```
第 0 层：初始已经腐烂的水果
第 1 层：1 分钟后腐烂的水果
第 2 层：2 分钟后腐烂的水果
第 3 层：3 分钟后腐烂的水果
...
```

因此，这道题的本质可以理解为：

> 从所有腐烂水果同时出发，计算腐烂状态传播到所有新鲜水果所需要的最短时间。

这和经典的“无权图最短路径”非常相似，只不过这里存在多个起点。

### 为什么必须是多源 BFS？

假设矩阵中有两个腐烂水果：

```
2 . . . 2
```

它们实际上会 **同时向外扩散**。

如果先从左边的 `2` 完整执行一次 BFS，再从右边的 `2` 开始，那么相当于错误地假设两个腐烂水果不是同时传播，会导致计算出来的时间偏大。

正确方法是初始化时：

```
q = deque([所有腐烂水果的位置])
```

然后让它们一起进入 BFS 第一层。

------

## 算法步骤

1. 遍历整个 `grid`：
   - 遇到新鲜水果 `1`，令 `fresh += 1`
   - 遇到腐烂水果 `2`，将其坐标加入队列
2. 从所有腐烂水果同时开始 BFS。
3. BFS 每一轮代表 **1 分钟**：
   - 记录当前队列长度 `len(q)`
   - 当前队列中的所有水果都属于同一分钟
   - 检查它们上下左右四个方向
   - 如果邻居是新鲜水果：
     - 将其改为 `2`
     - `fresh -= 1`
     - 将其加入队列，等待下一轮继续传播
4. 每处理完一整层 BFS：

```
time += 1
```

1. BFS 结束后：
   - 如果 `fresh == 0`，说明所有水果都已经腐烂，返回 `time`
   - 否则说明存在无法到达的新鲜水果，返回 `-1`

------

## Python 实现

```
from typing import List
from collections import deque


class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        # q 保存当前已经腐烂、并且之后可以继续向外传播的水果
        q = deque()

        # fresh 记录当前还剩多少新鲜水果
        fresh = 0

        # time 表示已经经过多少分钟
        time = 0

        rows = len(grid)
        cols = len(grid[0])

        # 第一次遍历：
        # 1. 统计新鲜水果数量
        # 2. 将所有初始腐烂水果加入队列
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 1:
                    fresh += 1
                elif grid[r][c] == 2:
                    q.append((r, c))

        # 上、下、左、右四个方向
        directions = [
            (0, 1),   # 右
            (0, -1),  # 左
            (1, 0),   # 下
            (-1, 0),  # 上
        ]

        # 只要还有新鲜水果，并且当前还有腐烂水果可以继续传播
        while fresh > 0 and q:
            # 当前队列中的所有节点属于同一层 BFS，
            # 即它们会在同一分钟向周围传播
            level_size = len(q)

            for _ in range(level_size):
                r, c = q.popleft()

                for dr, dc in directions:
                    nr = r + dr
                    nc = c + dc

                    # 检查是否越界，并判断邻居是不是新鲜水果
                    if (
                        0 <= nr < rows
                        and 0 <= nc < cols
                        and grid[nr][nc] == 1
                    ):
                        # 新鲜水果被感染
                        grid[nr][nc] = 2
                        fresh -= 1

                        # 下一分钟，它还可以继续感染其他水果
                        q.append((nr, nc))

            # 完成一整层 BFS，表示过去了一分钟
            time += 1

        # 如果仍然存在新鲜水果，说明这些水果无法被感染
        return time if fresh == 0 else -1
```

------

## `collections.deque` 说明

这里使用：

```
from collections import deque
```

`deque` 是 Python 标准库提供的 **双端队列（double-ended queue）**。

BFS 中最常用的两个操作是：

```
q.append(x)
```

将元素加入队尾。

以及：

```
x = q.popleft()
```

从队首取出元素。

这正好符合 BFS 的 **先进先出 FIFO** 特性：

```
先进入队列的节点
    ↓
先被处理
```

不推荐直接使用普通 `list`：

```
q.pop(0)
```

因为删除列表第一个元素时，后面的元素通常都需要整体向前移动，时间复杂度为：

```
O(n)
```

而：

```
deque.popleft()
```

通常是：

```
O(1)
```

因此，Python 中实现 BFS 时，`deque` 基本是标准选择。

------

## BFS 分层为什么能够表示时间？

例如：

```
2 1 1
1 1 0
0 1 1
```

初始状态：

```
2 1 1
1 1 0
0 1 1
```

初始腐烂水果是：

```
(0, 0)
```

第 1 分钟，它会感染：

```
(0, 1)
(1, 0)
```

第 2 分钟，这两个水果继续感染新的水果。

因此 BFS 的传播过程天然形成：

```
Level 0 → 0 分钟
Level 1 → 1 分钟
Level 2 → 2 分钟
Level 3 → 3 分钟
```

这就是为什么：

```
level_size = len(q)
```

非常重要。

它固定了“当前这一分钟能够传播的水果数量”。

只有这些水果全部处理完成之后，才能：

```
time += 1
```

------

## 一个容易忽略的重要细节：为什么一发现新鲜水果就立刻改成 `2`？

代码中：

```
if grid[nr][nc] == 1:
    grid[nr][nc] = 2
    q.append((nr, nc))
```

这里必须 **立即修改状态**。

假设两个腐烂水果同时连接到同一个新鲜水果：

```
2
|
1
|
2
```

如果我们只是：

```
q.append((nr, nc))
```

但是不立即把它改成 `2`，那么另一个腐烂水果检查到它时，仍然会认为它是新鲜水果，于是再次加入队列。

这可能导致：

- 同一个水果重复进入队列
- `fresh` 被重复减小
- 时间和状态计算出错

因此在 BFS 中有一个很重要的原则：

> **发现节点时就标记 visited，而不是等到取出节点时才标记。**

这道题直接利用：

```
grid[nr][nc] = 2
```

充当了 `visited` 标记，因此不需要额外维护：

```
visited = set()
```

------

## 时间复杂度

设：

- `m` 为矩阵行数
- `n` 为矩阵列数

第一次扫描整个矩阵：

```
O(m × n)
```

在 BFS 中，每个水果最多进入队列一次，每个位置最多检查四个方向：

```
O(m × n)
```

因此总时间复杂度为：

```
O(m × n)
```

------

## 空间复杂度

最坏情况下，队列中可能保存接近整个矩阵的节点：

```
O(m × n)
```

因此：

```
空间复杂度：O(m × n)
```

注意这里通常讨论的是 **额外空间复杂度**。

因为直接修改了输入矩阵：

```
grid[nr][nc] = 2
```

所以不需要额外建立 `visited` 矩阵。

# 2. 不使用队列的 BFS 模拟

## 核心思路

第二种方法本质上仍然是在进行：

> **按层 BFS**

只不过没有显式使用队列，而是通过不断扫描整个矩阵来模拟“一分钟过去了”。

这里额外引入状态：

```
3
```

表示：

> 这个水果在当前这一分钟刚刚被感染，但必须等到下一分钟才能继续感染其他水果。

因此：

```
2 = 当前分钟开始之前就已经腐烂
3 = 当前分钟刚刚腐烂
```

每一分钟完成之后，再统一：

```
3 → 2
```

------

## 为什么需要状态 `3`？

这是这种方法最关键的地方。

假设：

```
2 1 1 1
```

正确传播过程应该是：

```
初始：
2 1 1 1

1 分钟：
2 2 1 1

2 分钟：
2 2 2 1

3 分钟：
2 2 2 2
```

但是如果扫描矩阵时直接：

```
1 -> 2
```

第一次扫描到：

```
2 1 1 1
```

最左边的 `2` 会把第二个位置改成 `2`：

```
2 2 1 1
```

接下来扫描继续向右走时，又会看到刚刚生成的新 `2`，于是它马上继续感染：

```
2 2 2 1
```

然后继续：

```
2 2 2 2
```

最终算法会错误地认为：

```
1 分钟全部腐烂
```

实际上需要：

```
3 分钟
```

因此必须临时使用：

```
3
```

区分“上一分钟已经腐烂”和“这一分钟刚腐烂”。

------

## 算法步骤

1. 遍历矩阵，统计新鲜水果数量 `fresh`。
2. 当：

```
fresh > 0
```

时不断模拟下一分钟。

1. 每一分钟开始：

```
changed = False
```

表示这一分钟是否成功感染过新水果。

1. 扫描整个矩阵：
   - 只允许值为 `2` 的水果传播
   - 如果邻居是 `1`：
     - 改为 `3`
     - `fresh -= 1`
     - `changed = True`
2. 如果整个矩阵扫描结束后：

```
changed == False
```

但：

```
fresh > 0
```

说明剩余的新鲜水果永远无法被感染：

```
return -1
```

1. 再扫描一次矩阵：

```
3 → 2
```

1. `time += 1`

------

## Python 实现

```
from typing import List


class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        ROWS = len(grid)
        COLS = len(grid[0])

        fresh = 0
        time = 0

        # 统计新鲜水果数量
        for r in range(ROWS):
            for c in range(COLS):
                if grid[r][c] == 1:
                    fresh += 1

        directions = [
            (0, 1),   # 右
            (0, -1),  # 左
            (1, 0),   # 下
            (-1, 0),  # 上
        ]

        while fresh > 0:
            # 记录这一分钟是否感染了至少一个新水果
            changed = False

            # 第一遍扫描：
            # 让所有当前状态为 2 的腐烂水果进行传播
            for r in range(ROWS):
                for c in range(COLS):
                    if grid[r][c] == 2:
                        for dr, dc in directions:
                            nr = r + dr
                            nc = c + dc

                            if (
                                0 <= nr < ROWS
                                and 0 <= nc < COLS
                                and grid[nr][nc] == 1
                            ):
                                # 用 3 表示：
                                # 这一分钟刚刚腐烂，
                                # 下一分钟才能继续传播
                                grid[nr][nc] = 3
                                fresh -= 1
                                changed = True

            # 还有新鲜水果，但是已经无法继续传播
            if not changed:
                return -1

            # 第二遍扫描：
            # 将这一分钟刚腐烂的水果正式变成 2
            for r in range(ROWS):
                for c in range(COLS):
                    if grid[r][c] == 3:
                        grid[r][c] = 2

            time += 1

        return time
```

------

## 时间复杂度

这种方法虽然没有使用额外队列，但是时间复杂度明显更高。

每一分钟都需要扫描整个矩阵。

一次扫描需要：

```
O(m × n)
```

最坏情况下，腐烂可能一次只能向前传播一个单元格，因此最多可能经历：

```
O(m × n)
```

轮。

所以最坏时间复杂度为：

```
O((m × n)²)
```

也可以写成：

```
O(m²n²)
```

------

## 空间复杂度

除了几个变量之外，没有额外使用随输入规模增长的数据结构：

```
O(1)
```

因此：

```
空间复杂度：O(1)
```

这里之所以能够做到 `O(1)`，是因为直接利用输入矩阵中的：

```
1 / 2 / 3
```

来保存状态。

------

# 两种方法对比

| 方法             | 时间复杂度 | 额外空间 | 推荐程度           |
| ---------------- | ---------- | -------- | ------------------ |
| 多源 BFS + Queue | `O(mn)`    | `O(mn)`  | **最推荐**         |
| 扫描矩阵模拟 BFS | `O((mn)²)` | `O(1)`   | 可作为空间优化思路 |

代码面试中通常应该优先写：

```
Multi-source BFS + deque
```

因为它：

- 时间复杂度最优
- 逻辑直接
- BFS 层数自然对应分钟数
- 属于非常标准的面试解法

第二种方法更适合理解：

> 如果不保存 BFS frontier（当前边界），也可以通过额外状态标记模拟 BFS 层级，但通常需要付出更多时间复杂度。

# 常见错误

## 1. 只从一个腐烂水果开始 BFS

错误思路：

```
找到一个 grid[r][c] == 2
然后开始 BFS
```

问题在于所有初始腐烂水果实际上都在 **同时传播**。

因此必须先扫描整个矩阵，把所有腐烂水果都加入队列：

```
if grid[r][c] == 2:
    q.append((r, c))
```

然后再统一执行 BFS。

这就是：

```
Multi-source BFS
```

和普通单源 BFS 最核心的区别。

------

## 2. 忘记统计剩余的新鲜水果

如果只执行 BFS，却不记录还有多少新鲜水果，就很难判断是否存在无法到达的水果。

例如：

```
2 1 0
0 0 0
0 1 1
```

下面两个 `1` 与腐烂水果完全隔离，因此永远不会腐烂。

通过：

```
fresh
```

可以非常方便地判断：

```
return time if fresh == 0 else -1
```

每感染一个水果时：

```
fresh -= 1
```

最终如果：

```
fresh > 0
```

说明仍存在无法被感染的新鲜水果。

------

## 3. 每处理一个水果就增加时间

错误代码可能类似：

```
while q:
    r, c = q.popleft()
    time += 1
```

这是错误的，因为一分钟内可以有 **多个腐烂水果同时传播**。

例如当前队列：

```
[A, B, C]
```

它们都属于同一分钟。

所以应该先固定：

```
level_size = len(q)
```

再处理整层：

```
for _ in range(level_size):
    ...
```

最后统一：

```
time += 1
```

核心原则是：

> **BFS 的一层对应一分钟，而不是一个节点对应一分钟。**

------

## 4. BFS 中过晚标记水果已经腐烂

不推荐：

```
if grid[nr][nc] == 1:
    q.append((nr, nc))
```

等以后从队列取出来时再改状态。

因为在它真正被处理之前，其他节点可能再次发现这个水果，从而导致重复入队。

应该在 **第一次发现它时** 就立即：

```
grid[nr][nc] = 2
q.append((nr, nc))
```

这和一般 BFS 中：

```
visited.add(node)
```

应该发生在“入队时”而不是“出队时”是同一个原则。

------

# 面试中的算法总结

这道题最值得记住的不是“腐烂水果”这个场景，而是它背后的通用模型：

```
多个起点
    ↓
同时向周围扩散
    ↓
每次扩散代价相同
    ↓
求覆盖所有目标需要的最短时间
```

看到这种结构时，可以优先考虑：

```
Multi-source BFS
```

常见的类似题型包括：

- 多个感染源同时传播
- 火焰同时扩散
- 多个门到所有房间的最短距离
- 多个起点到其他位置的最近距离
- 从多个位置同时进行图上的逐层传播

一个很实用的判断方式是：

> **如果题目中出现“每一秒 / 每一分钟向相邻位置传播一步”，通常应该优先想到 BFS。**

如果又存在：

> **多个位置同时开始传播**

那么进一步考虑：

> **Multi-source BFS。**
